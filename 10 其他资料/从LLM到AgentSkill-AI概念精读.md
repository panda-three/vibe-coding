## 概念地图（视频主线：从底层往上搭）

**LLM → Token → Context → Context Window → Prompt → Tool → MCP → Agent → Agent Skill**

## ① LLM（大语言模型）—— 底层引擎

- **定义**：Large Language Model，大语言模型，简称大模型；几乎所有大模型都基于 **Transformer 架构**训练，它是大模型的底层引擎。
- **核心要点**：
  - Transformer 由 **Google 团队 2017 年**提出（论文《Attention is all you need》）；"Google 发明了火种，但真正点燃并引爆全世界的，是 OpenAI"。
  - **GPT-3.5（2022 年底）** 横空出世，是第一个真正达到可用级别的大模型；**GPT-4（2023 年 3 月）** 把 AI 能力天花板拉到新高度；时至今日 GPT-5.4 仍是业界标杆之一。
  - 如今赛道早已不是 OpenAI 独角戏，Claude、Gemini 等在各擅长的领域同台竞技。
  - **大模型工作的本质 = 文字接龙游戏**：预测下一个概率最高的词 → 吐出来塞回输入 → 再预测下一个 → 循环直到输出结束标识符。
- **例子**：问"马克的视频怎么样？" → 模型依次吐出"特别→的→棒" → 结束 → 完整回答"特别的棒"。
- **金句**："大模型本质上就是一个文字接龙游戏。"

---

## ② Token（基本单元）—— 大模型与文字之间的"翻译"

- **定义**：**Token 是大模型处理文本的最基本单元**，由 tokenizer（分词器）切分出来。
- **核心要点**：
  - 大模型是庞大的数学函数，只认数字、不认文字 → 中间需要 **tokenizer** 做翻译，负责两件事：
    - **编码**：文字 → 数字。分两步：①**切分**（把文本拆成最小片段 = Token）；②**映射**（每个 Token 对应一个数字 = TokenID，一对一绑定）。
    - **解码**：数字 → 文字。只有一步：映射（方向反过来）；不需要切分，因为模型每次只吐一个 token。
  - **Token ≠ 词**：没有明确的一对一关系。Token 是"模型自己学会的一套文本切分规则，切出来的每一块就是它一次能处理的最小单位"。
  - **换算参考**：平均 1 个 token ≈ **0.75 个英文单词** ≈ **1.5~2 个汉字**；40 万 token ≈ 60~80 万汉字 / 30 万英文单词。
- **例子**：
  - "马克的视频怎么样"恰好吃 4 个 token（≠4 个词）；
  - "马克的技术工作坊"在 OpenAI 分词页面被切成 **5 个 token**——"工作坊"被拆成"工作"+"坊"；
  - "程序员"被切成"程序"+"员"两个 token；
  - 英文常见词 hello、going 各 1 个 token，但 helpful 被拆成 help+ful；对勾符号"✓"需要 3 个 token 表示。
- **金句**："Token 才是大模型处理文本的最基本单元。"

## ③ Context（上下文）—— 大模型的"临时记忆体"

- **定义**：**Context 是大模型每次处理任务时所接收到的信息总和**，某种程度上可以看作大模型的临时记忆体。
- **核心要点**：
  - 大模型本质是数学函数，**没有记忆**。能"记住"之前的聊天，是因为每次发消息时，**背后的程序会自动把整段对话历史找出来一起发过去**。
  - Context 里装的不止用户问题和对话历史，还包括：**正在输出的每一个 token、工具列表、system prompt** 等。
- **金句**："Context 就是大模型每次处理任务时所接收到的信息总和。"

---

## ④ Context Window（上下文窗口）—— 容量上限

- **定义**：**Context Window 代表 Context 最多能容纳的 Token 数量**，即模型一次最多能处理多少 token。
- **核心要点**：
  - 主流大模型窗口都很大：**GPT-5.4 约 105 万 token、Gemini 3.1 Pro 约 100 万、Claude 约 100 万**。
  - 100 万 token ≈ 150 万汉字，**整套《哈利波特》全集都能装下**。
  - **超长资料不能整本塞给模型**（会撑爆窗口、成本失控）→ 用 **RAG（检索增强生成）**：从资料中抽取与用户问题最匹配的几个片段，只把片段发给模型 → 不受窗口限制、成本低很多。
- **例子**：上千页的公司产品手册 → RAG 只取相关几段话，而不是一整本书。
- **金句**："100 万 token 差不多就是 150 万个汉字，整个哈利波特全集的内容都能装下。"

## ⑤ Prompt（提示词）—— 给模型的具体问题或指令

- **定义**：**Prompt 是大模型接收的具体问题或指令**，接到输入后模型才开始运转。
- **核心要点**：
  - 不要想得太高端——Prompt 只不过就是给大模型的一个问题或指令。
  - **Prompt 怎么写直接决定输出质量**：模糊的 prompt（"帮我写一首诗"）可能得到古诗/现代诗/打油诗；好的 prompt 应该**清晰、具体、明确**。
  - **提示词工程（Prompt Engineering）= 研究怎么把话说清楚**；这个领域现在提的人寥寥无几——一方面门槛太低（本质就是把话说清楚），另一方面模型能力越来越强，含糊的提示词也能大致猜出意图。
- **例子**：模糊版"帮我写一首诗" vs 清晰版"请帮我写一首五言绝句，主题是秋天的落叶，风格要悲凉一点"。
- **金句**："Prompt 怎么写直接决定了大模型的输出质量。"

---

## ⑥ User Prompt vs System Prompt（两种提示词）

- **定义**：
  - **User Prompt（用户提示词）**：说明具体任务，是用户自己输入的。
  - **System Prompt（系统提示词）**：说明人设和做事规则，是**开发者在后台配置**的，用户看不到，但会一直影响模型行为。
- **例子**：数学辅导机器人——
  - System Prompt："你是一个耐心的数学老师，当学生问你数学问题的时候，不要直接给出答案，而要一步一步引导学生思考，帮助他们理解解题思路。"
  - User Prompt（学生在对话框输入）："3 + 5 等于几？"
  - 结果：模型回答"你手里有 3 个苹果，又拿了 5 个，现在一共有多少个呢？你可以数一数看。"——而不是直接说"8"。
- **金句**："有了它们的配合，大模型既能守住规矩，又能够完成你的具体需求。"

## ⑦ Tool（工具/函数）—— 让大模型感知外部环境

- **定义**：**Tool 本质上就是一个函数**：输入 → 内部操作（如调接口）→ 输出。它给大模型提供一套可调用的外部能力，让大模型能够**感知和影响外部环境**。
- **核心要点**：
  - **大模型的弱点**：无法感知外界环境（只是文字接龙，没法查实时数据）——问"今天上海天气怎么样"它会说"无法获取实时天气信息"。
  - **完整调用流程（四个角色）**：用户 → 平台 → 大模型 / 工具。
    - **平台 = 传话筒**（本质是一段代码）：负责上传下达——把用户问题+可用工具列表发给模型；按模型的调用指令真的调用工具；把结果回传给模型；再把模型整理好的人话转发给用户。
    - **大模型的职责有两个**：①**选择工具**（选哪个工具+生成工具参数）；②**归纳总结**（拿到工具结果后整理成人话）。
    - **工具的职责**：完成具体动作（如查天气）。
  - **关键认知（初学者最容易搞错）**：**调用工具的不是模型，是平台**。模型唯一的能力是输出文本——它只是输出一段"我想调用哪个工具、参数是什么"的指令，真正执行调用动作的是平台。
- **例子**：天气查询工具，输入参数（城市、日期）→ 内部调用气象局接口 → 输出天气信息。
- **金句**："模型能做的，仅仅只是输出一段文本，告诉平台它想要调用哪个工具。"

---

## ⑧ MCP（模型上下文协议）—— 统一的工具接入标准

- **定义**：**MCP = Model Context Protocol（模型上下文协议）**，本质是一套**统一的工具接入规范**。
- **核心要点**：
  - **痛点**：每个平台的工具接入规范不一样——同一个工具，ChatGPT 要按 OpenAI 规范写一套、Claude 按 Anthropic 写一套、Gemini 按 Google 再写一套，**要写三遍**。
  - **MCP 的解法**：工具开发者只按 MCP 规范**开发一次**，这个工具就能被所有支持 MCP 的平台使用。
  - 类比：**所有手机都用 Type-C 接口**，有了统一标准大家都方便。
- **金句**："MCP 就像是所有的手机都用 Type C 接口一样，有了统一的标准，大家都会方便很多。"

## ⑨ Agent（智能体）—— 能自主规划的系统

- **定义**：**能自主规划、自主调用工具、持续工作，直至完成用户任务的系统，称为 Agent。**
- **核心要点**：
  - 与单次工具调用的区别：Agent 会**一步一步思考当前情况、决定下一步该做什么**——多步调用工具 + 自主规划，已经"有了一定的自主规划能力"。
  - 市面主流 Agent 产品：**Claude Code、Codex、Gemini CLI** 等；经典构建模式：**ReAct、Plan and Execute** 等。
- **例子**（多步调用的完整链路）："今天这里的天气怎么样？如果下雨，帮我查一下附近有没有卖雨伞的店。"
  1. 模型思考 → 调用**定位工具**，拿到经纬度（-74, 40）；
  2. 再思考 → 调用**天气工具**（参数=经纬度），返回"有雨"；
  3. 再思考 → 符合"下雨找伞"条件 → 调用**店铺工具**（搜索雨伞），返回"附近 100 米有全家便利店卖伞"；
  4. 综合所有信息 → 输出最终答案。
- **金句**："我们称这种能够自主规划、自主调用工具，直至完成用户任务的系统为 Agent。"

## ⑩ Agent Skill（智能体技能）—— 给 Agent 看的说明文档

- **定义**：**Agent Skill 本质上就是一份提前写好、塞给 Agent 的说明文档**（Markdown），用来规定做事步骤和规则，把用户的私人规则/格式要求固化下来，避免每次提问都复制粘贴一大串。
- **核心要点**：
  - **文档结构分两部分**：
    - **元数据层（封面）**：至少两个属性——**name**（技能名字）+ **description**（技能是做什么的），告诉 Agent"这个技能叫什么、负责什么"。
    - **指令层**：从"目标"到文末，格式不做具体要求，说明白就行；通常写**目标、执行步骤、判断规则、输出格式及示例**。
  - **存放硬性规范（以 Claude Code 为例，别搞错）**：
    1. 在用户目录的 **`~/.claude/skills`** 文件夹下新建一个文件夹，**文件夹名必须与 Agent Skill 的名字相同**；
    2. 文件夹里新建一个文件，**文件名必须叫 `SKILL.md`（Skill 大写）**——这是"接头暗号"，随便起别的名字系统绝对不会认。
  - **加载机制（渐进式披露，省 token）**：启动时只读取**元数据层**（名称+描述）；**只有当用户问题与技能的名称/描述相关时，才会去读取指令层**。
  - 高级功能：运行代码、引用资源等。
- **例子**：出门小助手 go-out-checklist（出门清单）——
  - 私人规则：下雨带伞、光照强戴帽子、空气差戴口罩、风大穿防风外套、手机必带；
  - 输出格式：先来一句总结，再列出带原因的物品清单；
  - 指令层：先调定位工具 → 再调天气工具 → 按判断规则整理物品 → 严格按输出格式输出 → 最后给一个"输入/工具返回/必须输出"的完整示例。
- **金句**："Agent Skill 本质上就是你提前写好，塞给 Agent 的一份说明文档。"

## 体系总结（视频结尾回顾）

| 概念 | 一句话本质 |
|---|---|
| **LLM** | 大模型，所有 AI 技术的核心 |
| **Token** | 大模型处理数据的最基本单元 |
| **Context** | 大模型每次处理任务时接收的信息总和（临时记忆体），装着历史记录、系统规则、当前输入；基本单位是 Token |
| **Context Window** | Context 最多能存储的 Token 量 |
| **Prompt** | 当前给大模型下达的具体指令或问题；分 **User Prompt**（用户输入）和 **System Prompt**（开发者后台配置的人设与做事规则） |
| **Tool** | 大模型用来感知和影响外部环境的函数 |
| **MCP** | 统一工具接入格式的标准协议，开发者只需按一个标准做工具 |
| **Agent** | 能自主规划、自主调用工具、持续运作直至解决用户问题的程序 |
| **Agent Skill** | 给 Agent 看的说明文档，规定做事步骤和规则 |

**一句话收尾**：理解了这套概念框架，你就能看懂 AI 圈的各种新产品（Claude Code、Codex、Coze、OpenClaw……）——它们本质上都是在这个框架下运作的。
