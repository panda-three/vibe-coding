# 作业系统｜细节故事线 v3

## 一句话（不变，案例卡 C06 原口径）
给学生用的"上传＋批改"作业系统，解决"做完作业无法检查/提交"——一个老师用豆包手做出整套作业系统，还在长。

## 第〇步：收作业这件"小事"，为什么值得做个系统
- 场景：中职机房授课，每节课收作业，主要收 C 语言 `.c` 文件。
- 痛点（需求文档 1.1 原文）："收作业耗时、易漏、难统计"；学生视角（案例卡 C06）："做完作业无法检查/提交"。
- 比过 3 个方案（需求文档 4.2）：A 主机跑网页服务、学生浏览器提交（**推荐**）；B 共享文件夹拖拽（无法统计、易误放）；C 学生装客户端（逐台部署、机房电脑易还原）。
- 关键决策（需求文档 7，2026-08-31 确认）：**网页上传 + 自动归档**；不加访问口令；不做批量下载；主要收 `.c` 文件、单文件 ≤50MB。
- 沉淀：**需求文档是图纸，但第一版只做最小闭环**——图纸画全套，V1 只做"能上传"。

## V1：能上传——第一版就做这一件事
**触发**：先要"能用"，别的一律往后放。
**动作（代码/文档实读）**：
1. 学生端 4 步：打开浏览器 → 输学号姓名 → 选文件 → 点提交，约 10 秒；可重复提交覆盖旧文件。
2. 归档：文件按 `作业任务 / 学号_姓名_原文件名` 自动存进 `uploads/`——收作业的"收"字自动化。
3. 数据零成本：2 个 JSON（tasks/submissions）+ 1 个 uploads 文件夹，重启不丢。
4. 安全底线（虽然只是第一版）：扩展名白名单 13 种、单文件 ≤50MB、`safeName` 过滤非法字符、路径穿越防护。
5. 局域网零配置：Windows 跑 `start.bat`，学生机访问 `http://主机IP:3000`（Next.js 官方文档：`next start` 默认监听 `0.0.0.0`）。

**惊讶点①**：第一版**故意只做上传**——需求文档写了全套，但先跑通最小闭环。能上传、能归档，收作业这件事就变了。

## V2：班级管理——两个班作业不一样，混在一起就乱了
**触发（讲师口述）**：我有**两个班级**，两个班的作业可能不一样，混在一起没法看。
**动作（讲师口述，实现形态待核对）**：
1. 两个班各自有作业任务、各自管理、各自看板，不再一锅乱。
2. （待核对：班级字段/双任务的具体实现——当前 zy-system 代码是"任务"维度，无班级字段；是每班各建任务，还是有专门班级管理？）
**惊讶点②**：系统从"收得上"进化到"管得清"——触发它的是**老师自己的两个班**，不是产品经理。

## V3：自动批改——"每次点开太麻烦"逼出来的
**触发（讲师口述）**：每次都要点开逐份看，太麻烦了。
**动作（讲师口述）**：
1. **提前上传答案**——答案先入系统。
2. 系统自动对答案、出批改结果，老师不用逐份点开。
**（待核对：批改怎么实现——比对方式/是否 AI 参与/结果怎么呈现/当前代码未含批改模块，实际在哪套实现里）**
**惊讶点③（本版最值钱）**：**答案先行**——不是"作业收上来再想怎么改"，而是"先有标准答案，再把'改'自动化"。这是把老师的工作流倒过来设计。
**讲法金句候选**：`想自动化一件事，先把它拆成"答案"和"比对"。`

## V4：桌面宠物——做得快的同学，给个彩蛋
**触发（讲师口述）**：有的同学做得快，做完没事干。
**动作（讲师口述）**：做快/完成的同学，**奖励一个桌面宠物玩一玩**。
**（待核对：桌宠怎么发放——集成在系统里领取？还是单独作品/程序？触发条件是什么？）**
**惊讶点④**：系统不止管"交没交"，还能**激励**——把"做得快"变成奖励，全班有盼头。
**讲法金句候选**：`学生做得快，就给个彩蛋——系统也能当老师使。`

## V5：界面打磨——为讲这个案例，让它配得上自己（2026-10-02）
**触发**：要面向成人学生讲这个案例，原界面（蓝白素表单+表格页）太"朴素"，撑不起演示。
**动作（实做，代码可验证）**：
1. 全局视觉系统（globals.css）：靛蓝→紫品牌渐变；玻璃拟态；动画 keyframes（淡入/弹入/呼吸点/对勾绘制/行闪烁）。
2. 学生端：深蓝渐变+光斑+玻璃卡片；**拖拽上传**；提交成功 SVG 对勾动画；**学号姓名 localStorage 记忆**；"已提交可覆盖重交"徽章。
3. 教师端：实时看板——已提交人数**数字滚动动画**；**提交率卡片**（全班人数+渐变进度条）；**1 分钟内新提交 NEW 徽章+行闪烁**；文件类型彩色徽章；相对时间。
4. 验证：`npm run build` 通过；端到端跑通（建任务→提交→覆盖重交→打开文件）；无头 Chrome 截图确认渲染。
**惊讶点⑤**：数据层一行没改，只换"外衣"，观感从"工具"变"产品"——打磨不是重构，是给作品一个配得上它的样子。

## 数据与结果（贯穿，讲的时候直接念）
- 学生操作：**4 步、约 10 秒**完成一次提交（需求文档 4.3 设定值）。
- 规模设计：支持 **40~60 台学生机同时访问**；单文件上限 **50MB**。
- 存储：**2 个 JSON 文件 + 1 个 uploads 文件夹** = 全部数据，重启不丢。
- 安全：**13 种扩展名白名单** + **6 层校验** + 路径穿越防护。
- 实时：教师端 **5 秒轮询**，V5 后新提交 **1 分钟内 NEW 高亮**。
- 班级：**2 个班**（人数待核对），作业各自独立。
- 使用：真实机房部署、学生真实提交使用；做过直播演示（案例卡）。
- 哇点（案例卡 C06）：**一个老师用豆包手做出整套作业系统，还在长**。

## 让学生"惊讶"的 6 个钩子（讲法素材）
1. **不是一次做对，是 5 轮长出来的**：上传 → 管班 → 自动批改 → 桌宠 → 打磨，每一轮都是现实麻烦逼出来的，不是规划出来的。
2. **第一版只做一件事**：需求文档画了全套，V1 就做"能上传"——最小可用闭环，先跑通再长大。
3. **一个人零成本**：一个老师、一个豆包，无数据库、无服务器、无外网依赖。
4. **约束变能力**：机房没外网 → 资源全本地化；局域网零配置（官方文档 0.0.0.0）；小系统也做 6 层安全校验。
5. **答案先行的工作流反转**：不是"收上来再改"，是"先传答案、系统自动比"——把老师最烦的"逐份点开"自动化。
6. **系统也能当老师使**：做得快 → 桌宠奖励，把"激励"做进系统里；全链路 AI 承包（你不会写代码，也能造出系统）。

## 与课程主线衔接（供大纲/逐字稿/香稿用）
- **回扣 Day2 拆Feature 金句**："你把工作拆成几步，它就能干几步"——现场互动：让学员拆作业系统的四层（上传 / 管班 / 批改 / 激励），拆完对答案；故事线就是"一次只长一个 Feature"的活样本。
- **回扣 07 项目完善优化**：V5 打磨轮就是课程 07 节活案例——界面不满足需求，自然语言让 AI 优化（课程原话："页面风格不满足需求，直接在终端自然语言描述，让 AI 自动优化完善"）。
- **回扣 Day3 系统飞轮**："今天你造的是智能体，明天能长成系统"——从"能上传"长到"能管班、能批改、能激励"，还在长。
- **双三角点亮**：场景（两个班的真麻烦）＋审美（V5 打磨）＋数据（学生数据=资产）；基本功（动手做、跑起来、验证）。
