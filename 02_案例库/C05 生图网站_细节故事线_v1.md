# C05 生图网站｜细节故事线 v1（三版迭代·让学生惊讶）

## 一句话（不变）
给追求极致、日出图量高（可达几千张）的设计师，提供"高质＋实惠"的 AI 生图站（质量对标国外 GPT 模型）。

## 全景：三版迭代一图流

| 版本 | 触发 | 做了什么 | 结果 | 沉淀（skill） |
|---|---|---|---|---|
| 第〇步 | 朋友一句"设计师出图太贵了" | 逼成五行需求（有人/有痛/高频） | 一张图纸 | — |
| V1 粗糙版 | 先跑起来验证 | 需求文档→开发文档→AI 出第一版；对接第三方生图 API | 能出图、丑、能用；客户先用 | API 对接方法 |
| V2 可配置版 | 第三方接口不稳定 | 连续接多家 API；后台加"可配置"开关 | 接口挂一家，站不断；用户无感 | 多 API 配置方法 |
| V3 高大上版 | 用户说"不够高大上" | 找最佳实践→对标即梦→换皮不换骨 | 界面像产品；400+ 付费、200+ 年会员 | 对标改版方法 |
| V4 画布版（加功能） | 用户要"连续出图" | 复刻某网站的画布内容→做成**工作流**形式；沉淀**连续性生图**功能集 | 从"出一张"到"出一套"；从单次工具到工作台 | 连续生图方法 |
| V5 测试版 | 功能多了要测 | 让 AI 排查测试问题（如**域名不兼容**等） | 问题清零，能放心上线 | 测试排障方法 |
| V6 部署版 | 要正式跑起来 | **Supabase 数据库**（重点）＋ Worker 部署 | 站一直在线，数据有处存 | 部署方法 |

> 讲法主句：**它不是一次做对的，是三次改对的。** 每一次改，都有理由，不是瞎改。

## 第〇步：一句话 → 五行需求（沿用 v1，简）
- 朋友是设计师，AI 出图一张几毛，一天几百张，一个月成本不小 → "设计师出图太贵了"
- 逼成五行：给谁用（设计师）／解决什么（出图太贵）／现在怎么做的（自己找图/外包/硬扛）／贵在哪（一张几毛×一天几百张=一个月上千块）／愿不愿意换（能省一半成本就换）

## V1：粗糙版（先跑起来，对接第三方 API）

**流程（讲师口述，顺序待核对）**：
1. 先生成需求文档 → 再生成开发文档（口述为"先开发文档后需求文档"，见下"待核对"）→ 让 AI 先出一版粗糙的
2. 粗糙版 = 丑、能出图、能跑（v1 已落地：能跑/能用/先给人用）
3. **对接第三方 API**（本版核心新细节，待补实）：
   - 生图网站的本质 = 网页界面 ＋ 调用第三方 AI 生图接口
   - **第一步：调研多家接口文档**——不是拿到一家就接，先把几家生图 API 的接口文档都看一遍（比什么：接口稳定吗/参数全吗/价格多少/返回什么）
   - **第二步：把接口文档喂给 AI（喂文档法）**——基本做法就三步：
     1. **把接口链接给它**（接口地址）
     2. **把接口的参数给它**（请求参数：提示词/尺寸/数量/鉴权 Key）
     3. **把返回的结果给它**（返回结构：图片 URL 在哪个字段）
     → 它基本就能利用这个接口返回结果了（帮你写出调用代码、接入页面）
   - **提示词怎么写**（重点讲细）：
     - 别让 AI 猜接口，直接把文档当"参考资料"喂进去
     - 提示词模板候选：`"这是 XXX 生图接口的文档（链接+参数+返回示例），请帮我在我的网站里接入它：用户输入提示词→调这个接口→把返回的图片显示出来。"`
     - 一句话本质：**把接口文档喂给它＝先让它学会，再让它干活**（API 对接版的"先学最佳实践再干活"）
   - 坑（引出 V2）：第三方接口**不稳定**——时而慢、时而挂、时而出错
4. 零成本起步：一分钱没花，只投入时间精力（先验证再投入）

**惊讶点①**：第一版敢丑着上线，不憋大招。"先跑起来，再改。"

## V2：可配置版（接口不稳定 → 接多家 → 后台开关）

**触发**：第三方接口不稳定（V1 的坑，不是设计失误，是客观现实）
**动作（讲师口述）**：
1. 连续接了几家 API（多模型并存：Gemini＋即梦＋国外 GPT 模型——C05 工具表）
2. 后台加"可配置"功能：哪个模型展示/不展示、哪个模型干活，后台一个开关
3. 效果：接口挂一家，站不断——用户无感，网站照常出图

**惊讶点②（产品思维，本版最有价值）**：
- 这不是"技术问题"，是**产品思维**：把"接口不稳定"这个技术风险，转成"多供应商可切换"的产品能力
- v1 逐字稿块八只有"后台开关"一句，没讲**为什么要有开关**——V2 补上因果链：不稳定 → 多接几家 → 才需要后台可配置

**讲法金句候选**：`技术出问题不可怕，可怕的是没有"备胎"。`

## V3：高大上版（用户嫌难看 → 对标即梦 → 换皮不换骨）

**触发**：客户用两周，反馈"不够高大上""界面太素，像工具不像产品"
**动作**（v1 已落地，本版补"为什么找他"）：
1. 找最佳实践：谁是这个领域"高大上"的标杆？——即梦（生图产品，界面漂亮到让客户觉得"专业"）
2. 对标：不是抄它的图，是拆它的界面骨架（分几块/每块放什么/配色怎么配）
3. 换皮：`"参考即梦的界面风格，把我的生图网站升级成高大上版。"` → 换皮不换骨

**惊讶点③**：升级不是拍脑袋，是"先让 AI 学最佳实践，再让它干活"（回扣 D1下 主锤 G04）。

## V4：加功能——数字画布（连续性生图）

**触发**：用户用着用着提出新需求——单张出图不够用，要**连续出图**（v1 块九"加功能"阶段的一个大功能；不是重写，是接着长）
**动作（讲师口述，细节待核对）**：
1. **复刻**：完全复刻了**之前一个网站**上面的画布内容（具体哪个网站待补；=又一次"找对标→抽骨架→换皮"，跟 V3 同一招）
2. **做成工作流形式**：不是照搬页面，是把对方的画布能力拆成一个**工作流**（用户操作流：选画布→锁定风格→连续出图→保存/导出？——具体流程待核对），让 AI 按工作流实现
3. 加**数字画布**（digital canvas）——从"输入一句话出一张图"升级为"在画布上连续工作"
4. 在画布上**沉淀了很多"连续性生图"功能**（待核对具体功能清单，候选理解）：
   - 风格/主体锁定：出一张后，下一张保持同一风格/同一角色（不跑偏）
   - 参考图传递：上一张的图直接作为下一张的参考
   - 连续迭代：在已有图上改、加、延伸，而不是每次从零
   - 批量/系列出图：一次出一套（不同姿势/不同角度/不同场景）
5. 每做通一个功能，就把方法沉淀下来（开发 skill，形态待确认）

**惊讶点④（工作台思维）**：从"出图工具"到"设计工作台"——单张工具靠功能，工作台靠**连续性**；连续性的本质是"让 AI 记得上一张"（上下文/风格不丢）。

**讲法金句候选**：`出图工具赚单张的钱，画布工作台赚"一套"的钱——你要做哪种？`

## V5：测试——发现问题，让 AI 排障

**触发**：功能多了（V1~V4），要测；一测，问题冒出来
**动作（讲师口述）**：
1. 测试中发现很多问题，比如**域名不兼容**——很多用户访问这个域名时**加载很慢**（现象已确认；根因：图片资源/CDN/接口响应慢？待核对）
2. **这些问题全部让 AI 帮解决**：把报错信息/现象喂给 AI → AI 给出修法 → 改完再测
3. 循环：发现一个喂一个，直到问题清零

**惊讶点⑤**：测试不是人肉点，是把问题喂给 AI 排——**你不需要会修，你需要会描述。**
**讲法金句候选**：`报错不可怕，可怕的是你不把报错喂给 AI。`

## V6：部署——Supabase 数据库（重点讲）＋ Worker

**触发**：测完了，要正式上线，站要一直在线、数据要有处存
**动作（讲师口述，Supabase 已确认）**：
1. **Supabase 数据库（重点讲）**：
   - 存什么：用户、生成记录、图片 URL、**后台配置**（V2 的"模型开关"数据就存在这）
   - 为什么讲它：它是"一个人做产品"的数据库答案——免费额度起步、可视化建表、AI 也能直接操作
2. **Worker 部署**（具体平台待核对：Supabase Edge Functions／Cloudflare Workers？）：网站/接口跑在 Worker 上，不用买服务器、按量付费

**Supabase 是什么（官方文档精读版 2026-10-02，供讲课时用）**：
- 一句话：**开源的后端即服务（BaaS）**，被称为"Firebase 的开源替代品"；GitHub 已超 **10 万 star**（官方 blog 2026-04 披露），顶级开源项目
- 核心：每个项目一个**完整独立的 PostgreSQL 数据库**（不是阉割版/抽象层，100% 可移植、无供应商锁定）；**每日自动备份**（付费计划支持时间点恢复）
- 在数据库之上封装一整套：**用户认证**（Auth：JWT，邮箱密码/魔法链接/OTP/社交登录/SSO）／**自动生成 API**（建表即得 REST/GraphQL）／**文件存储**（Storage：S3 兼容、**全球 CDN 285+ 城市**、**图片在线缩放/压缩/转换**）／**实时订阅**（Realtime）／**边缘函数**（Edge Functions）／可视化运维面板（Table Editor 图形建表＋SQL Editor）
- **Worker 佐证**：Edge Functions＝服务器端 TypeScript 函数、全球边缘部署（靠近用户、低延迟）；官方用例明确包含"**编排调用外部 LLM/生图 API**（如 OpenAI）"和"按需图片生成"——生图网站的 Worker 极可能就是它（待用户确认）
- **AI-first（跟课程主线呼应）**：官方提供 **Agent Skills**（开源，含 SKILL.md，教 AI 编码代理正确用 Supabase）、**MCP server**（把 AI 直接连到项目）和 **Plugin**（MCP+Skills 打包一键装）——官方都"把开发方法做成 skill 喂给 AI"，印证 D1下 Skill 定义与讲师"沉淀开发 skill"的做法
- 免费额度（Free $0/月）：500MB 数据库/项目、**无限 API 请求**、自动备份、5GB 出站；上生产 Pro 约 $25/月
- 上手三步：注册→新建项目（选地区，约 1-2 分钟就绪）→Table Editor 图形化建表（不用写 SQL）→拿 URL＋anon key，几行代码就能读写
- 教学锚点：**数据库不是黑盒，是一个"点几下就有的云数据库，还自带接口"**——个人开发者不用搭服务器、不用写后端
- 与案例的连线：存用户/生成记录/图片 URL/后台配置（V2 开关数据）；Storage 的 CDN＋图片优化很可能就是"域名加载慢"的解法方向（待讲师确认根因）
- 来源：官方文档 getting-started/database/auth/storage/functions/ai-tools 等页（链接见文末）

**惊讶点⑥**：部署也是"AI＋现成平台"——**数据库用 Supabase、代码跑 Worker，一个人全搞定。**

## 数据与结果（贯穿，C05 已有）
- 成本：一张 7 毛 → 优化后 3 毛；1000 张省 400 元/天，一个月约 1.2 万

- 起点：零成本（一分钱没花）
- 哇点：零成本起步 → 400+ 付费、200+ 年会员；先验证再投入

## 让学生"惊讶"的 7 个钩子（讲法素材）

1. **不是一次做对，是三次改对**——迭代思维：V1 丑着上、V2 加备胎、V3 换皮
2. **一个人，零成本**，从朋友一句话做到 400+ 付费、200+ 年会员
3. **接口不稳定→接多家→后台可配置**：把技术坑变成产品能力（备胎思维）
4. **对标即梦**：升级有范本，不拍脑袋（换皮不换骨）
5. **数据算账**：7 毛→3 毛，1000 张省 400/天——不是靠感觉经营，是靠数据经营
6. **数字画布**：复刻标杆→拆成工作流→从"出一张"到"出一套"
7. **全链路 AI 承包**：对接（喂接口文档）→测试（喂报错）→部署（Supabase＋Worker）——**你只需要会"喂"，AI 就能干活**

## 附录A：开发工作流沉淀（来源：`10 其他资料/夙愿·AI Agent聪明度管理框架.md`）

> 讲师在生图网站项目里的真实开发方法（夙愿框架）。**素材层**：供写逐字稿/香稿取用；**课堂上不展开框架名词**（学员水位，只取"怎么用"的故事）。用户 10-02 指示：开发工作流、测试、部署三块在此补充沉淀。

### A1 · 9 步闭环工作流（原文）
```
Issue → Grade(对齐需求) → 原型(验证方案) → To PRD(沉淀文档)
    → To Issue(垂直切片) → TDD(测试驱动写代码)
    → 代码审查(核弹级) → E2E测试(端到端验证)
    → 手工分组测试 → 完成 / Bug Fix(7阶段修复) → 循环
```

### A2 · 与生图网站 V1~V6 的对应（讲课时可隐形使用）
| 案例版本 | 对应工作流步骤 | 说明 |

| V1 初版 | Issue→Grade→To PRD→原型 | 朋友一句话＝Issue；五行需求＝Grade 榨干；需求/开发文档＝To PRD；AI 出第一版＝原型 |

### A3 · 测试方法补充（V5 深度，讲"让 AI 排障"时取用）
- **TDD**：先写测试（红灯）→写最少代码让它过（绿灯）→重构——代码有客观裁判
- **E2E 测试**：让 AI 用浏览器/桌面操作跑端到端；**遇 Bug 只记录事实和复现步骤，不写修复建议**（防打补丁）
- **手工分组测试**：一条路径走完（注册→登录→充值→使用），不来回切——最后一道防线
- **Bug Fix 7 阶段**：读知识沉淀→建验证循环（代码级验证不靠看）→假设＋探针定位根因→修复验证→沉淀（业务术语→Context 文档／陷阱→陷阱文档／架构决策→ADR 文档）
- 案例落点：`域名不兼容＝加载很慢` → 把现象喂给 AI → AI 定位根因→修复→再测→清零（＝7 阶段简化版，全程 AI 执行）

### A4 · 部署补充（V6 深度）
- 完整架构：**前端网页 ＋ Supabase（数据库/认证/存储/自动 API）＋ Edge Functions（Worker，编排调用生图 API）＋ Storage CDN（图片分发）**
- 部署四步：①建 Supabase 项目（选地区）②Table Editor 建表（用户/生成记录/图片 URL/后台配置）③Edge Function 部署（Dashboard/CLI，按用户口述"Worker"推断，不展开）④前端连 URL＋anon key，几行代码读写
- 与 V2 连线：模型开关数据存 Supabase 表；后台配置页＝读表→切换模型
- 与"加载慢"连线：图片走 Storage＋全球 CDN（285+ 城市）＋图片在线缩放/压缩——解决方向的佐证（根因以讲师实情为准）

### A5 · 知识沉淀飞轮（呼应"每做一版沉淀 skill"）
- 每个会话都是全新的→沉淀三类：**业务术语→Context 文档／已知陷阱→陷阱文档／技术决策→ADR 文档**
- 每次开新会话→先读沉淀→干活→发现新东西→沉淀回去→下次起点更高
- 这就是"六版做下来，把方法沉淀成 skill"的**方法论底座**，与 D1下 Skill 定义（流程+配方+工具+材料打包）互相印证：夙愿沉淀的是"上下文/知识"，Skill 沉淀的是"可执行方法"，本质都是**让下次不用重新摸索**
