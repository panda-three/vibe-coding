# 作业系统｜细节故事线 v2

## 一句话（不变，案例卡②原口径）
给学生用的"上传＋批改"作业系统，解决"做完作业无法检查/提交"——一个老师用豆包手做出整套作业系统，还在长。

## 全景：版本迭代一图流

## 第〇步：收作业这件"小事"，为什么值得做个系统
- 场景：中职机房授课，每节课都要收作业，主要收 C 语言 `.c` 文件。
- 痛点（需求文档 1.1 原文）："收作业耗时、易漏、难统计"；学生视角（案例卡②）："做完作业无法检查/提交"。
- 比过 3 个方案（需求文档 4.2）：A 主机跑网页服务、学生浏览器提交（**推荐**）；B 共享文件夹拖拽（无法统计、易误放）；C 学生装客户端（逐台部署、机房电脑易还原）。
- 关键决策（需求文档 7，2026-08-31 确认）：**网页上传 + 自动归档**；不加访问口令；不做批量下载；主要收 `.c` 文件，兼容常见格式、单文件 ≤50MB。
- 沉淀：先把"收作业"拆成教师端/学生端/系统三层需求，再动手——**先写需求再开发**。

## V1：功能版——"没数据库、没外网，也撑起一个系统"
**流程（代码/文档实读）**：
1. 技术选型：Next.js 16（App Router）+ React 19 + Tailwind CSS 4 + TypeScript；本地文件系统存储，无数据库、无外网依赖（README）。
2. 学生端：打开浏览器 → 输学号姓名 → 选文件 → 点提交，**4 步约 10 秒**（需求文档 4.3）；可重复提交，新文件覆盖旧文件。
3. 教师端 `/teacher`：新建作业任务、切换当前作业、5 秒轮询实时看板、点击"打开"直接看学生代码。
4. 归档规则：文件按 `作业任务 / 学号_姓名_原文件名` 自动归档到 `uploads/`（lib/store.ts）。
5. 安全校验 6 关（代码实读）：① 任务存在 ② 任务处于激活态 ③ 扩展名白名单（.c/.h/.txt/.md/.zip/.rar/.7z/.doc/.docx/.pdf/.png/.jpg/.jpeg 共 13 种）④ 单文件 ≤50MB ⑤ 打开文件时 `startsWith` 防路径穿越 ⑥ `safeName()` 过滤 `\ / : * ? " < > |` 非法字符。
6. 零数据库设计：数据只存 2 个 JSON（`data/tasks.json` + `data/submissions.json`）＋ 一个 `uploads/` 文件夹；重启不丢（README）。
7. 局域网访问：Windows 主机跑 `start.bat`（自动 build + start），学生机访问 `http://主机IP:3000`——**零配置**，依据 Next.js 官方文档：`next start` 默认监听 `0.0.0.0`（"Useful for making the application available for other devices on the network"）。

**真实使用（讲师确认 2026-10-02）**：已在真实机房部署使用，学生真实提交过作业；做过直播演示。→ 案例不是"造完就摆着"，是真的在课上用起来的。
**过程注记（待核对）**：开发过程存在卡点/返工，具体细节待讲师口述补充（不编造）。

**惊讶点①**：没有数据库、没有云、没有外网——两个 JSON 文件加一个文件夹，就是一个能用的"系统"，而且真实机房在用。数据不是只有数据库一种存法。

## V2：打磨版——同一套接口，观感从"工具"变"产品"
**触发**：要面向成人学生讲这个案例，原界面（蓝白素表单 + 表格页）太"朴素"，撑不起演示。

**动作（2026-10-02，纯前端，后端与数据结构零改动）**：
1. 全局视觉系统（globals.css）：品牌色改为靛蓝→紫渐变；玻璃拟态卡片；一套动画 keyframes（淡入上浮/弹入/呼吸点/对勾绘制/行闪烁）。
2. 学生端：深蓝渐变背景+光斑+玻璃卡片；文件区支持**拖拽上传**（拖入高亮放大）；提交成功 SVG 对勾动画；**学号姓名 localStorage 记忆**（第二次打开免输入）；"已提交过，可覆盖重交"徽章。
3. 教师端：升级成实时看板——已提交人数**数字滚动动画**；**提交率卡片**（全班人数只存本机 localStorage，带渐变进度条）；**最近 1 分钟新提交 NEW 徽章 + 行闪烁**；文件类型彩色徽章（.c 蓝 / .pdf 红 / .zip 琥珀）；相对时间（"3 分钟前"）。
4. 验证：`npm run build` 通过；端到端跑通（建任务 → 提交 → 覆盖重交 → 打开文件）；无头 Chrome 截图确认两页渲染。

**惊讶点②（本版最有价值）**：数据层一行没改，只是"外衣"换了——它就像另一个产品。打磨不是重构，是给已有的东西一个配得上它的样子。
**讲法金句候选**：`界面不是装饰，是作品的第一印象。` ／ `同一套数据，换个样子，学生就觉得这系统"高级"。`

## 数据与结果（贯穿，讲的时候直接念）
- 学生操作：**4 步、约 10 秒**完成一次提交（需求文档 4.3 设定值）。
- 规模设计：支持 **40~60 台学生机同时访问**；单文件上限 **50MB**（需求文档 6 非功能需求）。
- 存储：**2 个 JSON 文件**（tasks + submissions）+ **1 个 uploads 文件夹** = 全部数据，重启不丢。
- 安全：**13 种扩展名白名单** + **6 层校验** + 路径穿越防护。
- 实时：教师端 **5 秒轮询**，V2 后新提交 **1 分钟内 NEW 高亮**。
- 部署：`start.bat` 一键启动，可放 Windows"启动"文件夹开机自启。
- 使用：**已在真实机房部署使用 + 直播演示过**（讲师确认）。
- 哇点（案例卡②）：**一个老师用豆包手做出整套作业系统，还在长**。

## 让学生"惊讶"的 6 个钩子（讲法素材）
1. **不是一次做对**：需求（第〇步）→ 功能（V1）→ 打磨（V2），至少 3 轮才到"能讲"的样子，每轮都有理由（V1 开发中还有卡点/返工，细节待补）。
2. **一个人零成本**：一个老师、一个豆包，无数据库、无服务器、无外网依赖——起步成本为零，只投入时间。
3. **约束变能力**：机房没外网是限制？那就把字体、资源全部本地化；局域网访问零配置（`next start` 默认 0.0.0.0，官方文档）——约束不是限制，是设计输入。
4. **零数据库也能做系统**：两个 JSON + 文件夹撑起整个系统，重启不丢——"数据不是只有数据库一种存法"。
5. **安全不是大厂专属**：一个课堂小系统也做了 6 层校验：白名单、大小限制、路径穿越防护、非法字符过滤——小系统也有专业底线。
6. **全链路 AI 承包**：需求文档 → 代码 → 打磨，全部通过豆包自然语言驱动完成——"你不会写代码，也能造出系统"（回扣案例卡②哇点）。
