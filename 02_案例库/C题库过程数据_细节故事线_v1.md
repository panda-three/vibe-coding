# C 题库过程数据｜细节故事线 v1

## 一句话

做 C 语言题库，沉淀的不只是真题（PDF→MD），**更是「过程数据」——第一版讲解稿/第二版讲解稿、第一版答题思路/第二版答题思路**。好讲法是改出来的，数据是边干边攒的复利。

## 背景

- 讲师做 C 语言教学，把真题从 PDF 整理成结构化 MD，并在反复教学中沉淀讲解稿和答题思路。
- 核心洞察：**最值钱的不是"题"，是"你怎么把题讲明白"的过程。**

## 数据全景（四类）

| 数据 | 对应三类数据 | 说明 |
|---|---|---|
| 考纲 | 标准 | 哪些考点、什么难度 |
| 真题（PDF→MD） | 结构化 | 题目/考点/答案/解析 |
| 学生错题 | 反馈 | 哪些题错得多、错在哪 |
| 讲解稿/答题思路（多版本） | 版本化 | 好讲法、好思路的演进 |

## 成品锚点：「讲解稿版本演进」的结构（不绑定具体题，课堂拿真实题演示）

> 经讲师拍板（2026-10-03）：**不使用 AI 编的具体题与数字（如"for 循环 1–100、60% 漏 i++"），只讲"讲解稿怎么演进"的结构。**

任何一道真题，都可以这样演进：
- **第一版讲解稿（讲步骤）**：只说"先做什么、再做什么"。
  → 干，学生只记住步骤，不理解为什么。
- **第二版讲解稿（加类比、加画面）**：把抽象概念比作生活里的东西，让学生"看得见"。
  → 有类比、有画面，学生真正理解。
- 🔑 这就是「**讲解稿版本化**」：好讲法不是一次想到的，是讲完一遍、看学生反应、再改出来的。

**配套（对应三类数据）**：
- 考纲（标准）：这道题要掌握哪些知识点；
- 学生错题（反馈）：这道题大家最容易在哪一步出错（课堂用真实题，不编比例）。

## 操作步骤（B 型流程）

1. 真题 PDF → MD：用 **MinerU** 工具转换（PDF 转 MD 会失真），转完**人工再求证**；结构化为题目/考点/答案/解析；
2. 对着考纲打标签（考点、难度）；
3. 每讲一次，保留讲解稿版本，标注改进点；
4. 记录学生错题，回填为反馈；
5. 相似题归类，形成可复用的题库。

## 核心认知点

1. **过程数据最值钱**：你的"两版讲稿/两版思路"是 AI 无法凭空生成的私有资产。
2. **版本化**：好讲法、好思路都是改出来的，要留痕。
3. **数据是边干边攒的复利**：不是先做完再用，是边教边攒。
4. 呼应主线：**AI 复制的是你的逻辑**——你把"讲题逻辑"沉淀成数据，AI 才能替你规模化。

## 惊讶钩子

- **反差**："别人存的是题，你存的是'怎么把题讲明白'——这才是别人抄不走的。"
- **现场演示**：同一道题，念第一版讲稿（干）vs 第二版讲稿（空盒子类比），学员立刻感到差别。
- **提问**："你教了这么多遍，那些'改了好几次才讲顺'的讲法，存下来了吗？"
