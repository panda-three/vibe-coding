# 01 一堂 CLI与快速上手



## 1\.1 一堂CLI是什么？

> **CLI**的全称是 Command Line Interface，命令行接口。


简单说，就是把一堂的核心产品面向命令行和产品开放，简单来说一句话：**从此之后，你的Agent可以自由使用一堂了。**



一旦你们正式安装上，你们的所有Agent，不管是Codex、WorkBuddy还是龙虾，就全面接入了科学体系，接入了业内最高水平的上下文，就接入了Partner协作体系。

> **Partner**，指一堂围绕具体方法和任务设计的AI专家 ，例如科学决策·ROI搭档，清单体笔记·高级助理。
> 
> 开通思考版或以上套餐后，在能够执行命令的Agent环境中完成CLI安装与授权，就可以在对话框里用日常语言布置任务，具体命令交给 Agent 执行。




我们打开了三套系统：

1. **课程系统：**可以浏览各个课程、列表清单。

2. **YAI系统：**你的对话、笔记、获取数据包。

3. **作业系统：**你的作业、评分点评、Candy。

> 说明：AI直接写作业和拉逐字稿是底线红线，不能破。

## 1\.3 怎么知道安装和登录成功了？

按照 Agent 的提示完成浏览器授权，再回到 Agent，看下面几项是否都已完成：

| 步骤      | 由谁操作                          | 成功时应该看到什么                                    |
| ------- | ----------------------------- | -------------------------------------------- |
| 确认安装    | Agent 运行 `whyai --version`。   | 能显示版本号；Agent核对它与安装页当前发布的版本一致。                |
| 核对登录环境  | Agent 按上面的登录命令指定 Gateway。     | 终端显示的 Gateway 是 `https://ai-pre.yitang.top`。 |
| 完成浏览器授权 | 你在打开的页面登录，并按提示完成授权。           | 页面提示授权成功；回到终端后，Agent 确认 CLI 已登录。             |
| 查询一次    | 让 Agent 搜索“清单体”相关的官方 Partner。 | 返回真实的 Partner 名称和简介，说明这项查询已能使用。              |

浏览器没有自动打开时，让 Agent 把本次登录生成的授权链接给你，在浏览器中打开后继续。授权页面可能跳转到一堂统一登录，连接环境以终端显示的 Gateway 为准。

更换电脑，或更换Agent的执行环境后，需要重新让Agent检查：一堂 CLI 是否装好、账号是否已经登录，账号是否已过期。

## 2\.2 进阶｜把几种能力接起来，完全一件事情


刚才都是单个维度，单个任务，那如果我们把各个任务串联在一起呢？



熟悉单次调用后，可以直接交代一个完整目标，让 Agent 根据需要多次调用一堂的能力。比如，把一次活动的复盘记录，做成一份团队汇报。

> 我们做了一场 30 分钟线上分享，目标是 40 人报名、25 人到场、8 人预约体验；实际是 60 人报名、18 人到场、3 人预约。报名时没有问大家想解决什么工作问题，也没调查未到场和未预约的原因。有人说是提醒太少，但目前没有证据。下一场依然只有 30 分钟，最多投入 2 小时准备，没有额外广告预算。
> 
> 

把材料交给 AI，再说明希望它怎样完成任务：

> 请用一堂 CLI，先找双三角 Partner 帮我梳理复盘盲区，再让清单体 Partner 整理成行动清单，最后让十指讲香 Partner 帮我把下一步的价值讲清楚。把几步结果接起来，交给我一份简短的汇报提纲。没有的信息就标“待确认”。
> 
> 


本次实际完成了三步接力：

|调用的 Partner|这一轮帮你做什么|
|---|---|
|一堂双三角·挖掘师|找出需要补充的证据，例如用户的工作需求、未到场和未预约的原因。|
|清单体笔记·高级助理|承接原始材料和复盘线索，整理下一步的建议动作，标出待确认事项。|
|十指讲香·价值感专家|承接前两步结果，讲清这些动作为什么值得做，形成团队汇报稿。|

Agent 最后整理出了 3 分钟汇报稿，把“发生了什么、还缺什么证据、下一步准备做什么”接在一起。准备时间的分配是建议，负责人、日期和实际效果仍保留为待确认。




**你负责说清目标，Agent 负责把材料和各轮结果传下去。**一次工作可以先查资料、再做分析、再整理表达；过程中有新信息，也可以随时补充。

## 3\.4 找 Partner，并开始调用

|想做什么|命令|一句话说明|
|---|---|---|
|找官方 Partner|`whyai --json partners search "清单体" --scope official`|按名称和描述搜索，核对角色是否适合任务。|
|核对完整名称|`whyai --json partners resolve "清单体笔记·高级助理"`|使用查询得到的完整名称；重名时改用 ID。|
|查看某个 Partner|`whyai --json partners get PARTNER_ID`|读取查询结果对应的 Partner 信息。|
|查看对话参数|`whyai chat --help`|核对材料、模型、会话和搜索等选项。|

**开始一段新对话：**

```Bash
whyai --json chat "请把这段记录整理成清单：开会前明确目标，会后确认行动项。" --partner PARTNER_ID --no-memory
```

**继续刚才的对话：**保存首轮返回的 `conversation_id`，把它填进下一条命令。

```bash
whyai --json chat "请把待确认的信息单独列出来。" --conversation CONVERSATION_ID --no-memory
```

**把本地文件作为材料交给 Partner：**

```bash
whyai --json chat "请整理这份材料，提取结论与待办。" --partner PARTNER_ID --file report.pdf --no-memory
```

将 `report.pdf` 换成实际文件路径。`--file` 会上传并附加文件；对话调用会生成会话和消息记录，并按实际规则计入用量。

常用选项：`--model MODEL_ALIAS` 指定模型，`--web-search` 开启联网搜索，`--knowledge-base` 开启一堂知识库。具体可用性仍以账号权限与服务端返回为准。



换另一位 Partner 时，应新建对话，并把需要的前序材料一并传入。已有 `--conversation` 时，再加 `--partner` 不会切换角色。



`--no-memory` 表示本次请求禁用记忆；它仍会产生会话和消息记录。需要时每轮都添加。`--continue` 用于请求续完上一条回答；补充新要求时，像上例直接写追问内容即可。



## 3\.5 回看结果，交给下一步

|想做什么|命令|一句话说明|
|---|---|---|
|列出历史会话|`whyai --json conversations list --page 1 --page-size 20`|先按实际列表定位要继续的会话。|
|回看一段对话|`whyai --json messages list CONVERSATION_ID --all`|读取指定会话的全部消息。|
|导出对话<br>|`whyai conversations export CONVERSATION_ID --format md --output conversation.md`|读取远端对话，保存为本地 Markdown 文件。|
|把本地成果保存为 YAI 笔记|`whyai notes create --title "行动清单" --content @ideas.md`|读取本地 `ideas.md` 的文本，在 YAI 中新建笔记。|

`--json` 是让结果按固定格式返回，方便 Agent 读取字段和传给下一步。`whyai yitang` 已经默认输出这类结构，不要写成 `whyai --json yitang …`。





# 04 遇到问题怎么办

先看卡在哪一步：命令没找到、登录没完成、功能没有权限，还是取回的内容不够。把正在执行的命令和错误原文告诉 Agent，它会更容易判断下一步。



## 4\.1 命令或连接没有跑通


|你看到的现象|可以怎么处理|
|---|---|
|提示 command not found，或无法识别 whyai|让 Agent 检查当前执行环境是否安装了 CLI，以及命令路径能否被找到。尤其确认是否换到了远程电脑或其他环境。|
|AI 直接回答，没有实际查询|明确说“请使用一堂 CLI 实际执行查询，并告诉我返回了哪些来源”。同时确认这个 Agent 有命令执行能力。|
|显示未登录、登录过期|YAI与一堂业务需要分别确认登录。|
|浏览器完成授权，命令仍失败|回到发起登录的终端或 Agent，查看是否明确完成；然后重新检查状态和一次实际查询。失效链接需要重新发起。|

## 4\.3 常见问题FQA

|Q：可能的问题|A：回答|
|---|---|
|CLI 和网页端的数据互通吗？|互通。使用同一账号时，CLI 创建或继续的会话、Partner 使用记录、笔记、分享和用量会与网页端使用同一后台数据|
|哪些套餐可以使用 CLI？|思考版、决策版或领航版订阅，并且有剩余额度。体验版、仅有手工余额或仅有赠送额度不能获得正式 CLI 业务访问资格；帮助、版本、登录、退出、状态和升级命令不受此限制。|
|CLI 支持哪些系统？|官方安装说明支持 macOS、Linux 和 Windows，需要 Node\.js 20 或更高版本。安装到用户可写目录，不需要管理员权限，也不需要全局 npm 安装。|
|如何登录 CLI？|whyai login|
|网页对话和一堂 CLI 调用共用额度吗？|共用同一账号的套餐额度池，但计量方式不同：网页模型对话按模型 token 用量结算；一堂 CLI 请求按成功响应的请求/响应 body 字节结算。|
|CLI 会自动升级吗？|会。|
|CLI 提示登录过期怎么办？|WhyAI access token 会自动刷新；若收到 HTTP 401 或明确的 token 无效/过期提示，重新运行 `whyai login`。普通 HTTP 403 通常表示权限不足，不应反复登录，也不会自动重放刚才的一堂业务操作。|
|CLI 显示有余额，为什么仍不能使用？|正式 CLI 业务访问需要同时满足：账号正常、当前有真实付费思考/决策/领航订阅、套餐未过期、可用额度大于 0、没有未结清用量。只有赠送余额、体验版或手工加额度并不自动获得 CLI 资格。运行 `whyai billing access --json` 查看拒绝原因。|
|CLI 提示 `command not found: whyai` 怎么办？|先运行安装器打印的 PATH 设置；macOS/Linux 通常需要把 `~/.local/bin` 加入 PATH，Windows 通常需要把 `%LOCALAPPDATA%\WhyAI\bin` 加入用户 PATH。重新打开终端后运行 `whyai --version`。若系统已有另一个同名命令，官方安装器会拒绝覆盖，应使用新的可写 `--prefix` 或联系支持。|
|“额度”是聊天次数吗？|不是固定次数。网页对话按模型实际返回的输入、输出等 token 使用量结算；不同模型、上下文长度、附件、搜索结果和回复长度会产生不同消耗。同样一句问题在不同上下文中消耗可能不同。|
|额度什么时候刷新？|订阅额度按购买日对应的月度周期刷新，并显示“下次刷新时间”。不是统一在每月 1 日刷新。|
|未用完的额度会跨月结转吗？|不会。订阅额度在当前周期结束时失效，不跨周期结转。|
|体验版有效多久？能重复领取吗？|当前配置为一次性 30 天体验，少量对话额度 。不能重复领取。|
|没有有效订阅，可以只买补充包吗？|不可以。补充包依附于当前有效付费订阅周期；无有效订阅或账号使用专属测试权益时，页面会禁用购买。|
|月付套餐会自动续费吗？|目前只有月付自动续费，页面会显示“按月连续订阅”和“次月起价格”，并提示购买时阅读支付页面的协议和续费说明。|
|如何取消未支付订单？|“套餐与用量”页面会显示当前订单。处于等待支付状态时，可以重新打开支付页或取消订单；如果订单状态查询超时，可稍后刷新。不要为了“卡住”而反复创建多笔订单。|
|如何取消自动续费或已生效订阅？|可以在微信取消，也可以找班班取消。|
|支付成功但套餐没有生效怎么办？|不要重复支付。先在套餐页刷新订单状态，记录订单号、支付时间和金额，通过客服/班主任提交。系统对“已支付但权益激活需人工处理”的情况有专门错误状态，售后需要执行核查、补发或退款。|
|支持哪些支付方式？|目前支持微信订阅，具体支付取决于用户的微信支付配置。|
|套餐到期或额度用完后，历史数据还在吗？|额度用完会阻止新的计费请求，但不会自动删除历史对话和笔记。套餐降档后，超出新笔记上限的历史笔记仍可查看、编辑和删除，只是不能继续新建。账号数据的最终保存仍受用户删除、注销和隐私政策约束。|
