## 二、香稿和PPT的边界：一张表说清

| 内容类型 | 属于香稿（老师嘴说） | 属于PPT（学员眼看） |
|---|---|---|
| 任务指令 | 补充说明、催促、安抚 | **指令本身整句上屏**（做什么、几步、多久） |
| 提示词原文 | 念出来 | **整句上屏，学员要照抄** |
| 公式/模板 | 解释怎么用 | **公式本身上屏，学员要收藏** |
| 案例原文 | 念案例 | **案例原文+AI回复都上屏**（左右对比） |
| 名词解释 | 展开讲比喻 | **一个词 + 一句定义**，比喻放正文小字 |
| 金句 | 停顿念出来 | **大字号居中，一屏一句** |
| 章节切换 | "好，接下来我们……" | **只放章节号+短标题**，不要解释 |
| 桥接过渡 | "下一段""先动手""答案先放一放" | **不上屏，直接删** |
| 演示动作 | "回车""我点一下""看出来了" | **不上屏，PPT上只留最终结果截图** |
| 情绪铺垫 | "好玩吗？""说实话有点普通" | **不上屏** |
| 悬念钩子 | "猜要多久？""它们怎么来的？" | **标题可以是问题，但不要把"不用说出来""等会对答案"这种提示语上屏** |
| 老师的私人备课提示 | —— | **放备注栏，不上屏**（你写的"动画效果""加token网站演示""不反过来挑他"） |

## 四、以后从香稿转PPT的操作规则

1. **标题只写"这一页叫什么"**——一个名词、一个短问句、或一句金句。超过15个字就砍。解释性长句一律放正文。
2. **正文只放三类东西**：指令步骤、提示词/公式/模板原文、案例对比。其余全删。
3. **桥页/过渡页默认不做**。只有当两章之间内容跳跃极大、学员需要一个明确的"换脑"信号时，才做一页纯章节号+短标题。
4. **演示动作描述不上屏**。PPT上只留"我打了什么字"和"出来了什么"，中间的回车、点击、停顿都是老师的事。
5. **金句页和内容页比例控制在 3:7 左右**，不要做到接近一半。
6. **工具准备页不能漏**。实操课开场前必须有一页交代"今天用什么工具、点哪里进哪个模式"。
7. **名词页标题 = 名词本身**（大模型-LLM / Token / 上下文 / 提示词 / 工具 / 智能体 / Skill / Vibe Coding），副标题才放比喻解释。
8. **提问式标题优先于陈述式标题**——"提示词如何写呢？"比"一句话的公式：角色+任务+背景+要求+格式"更适合上屏。
9. **老师的备课想法写备注，不上屏**。动画提示、备用方案、互动节奏控制，都放notes。
10. **不要为了"结构完整"硬凑页**。原版P23命名页、P51行动页、P52封底——都是为了凑结构加的，实际讲课根本不需要单独成页。

## 五、一句话总结

> **香稿是老师的剧本，PPT是学员的黑板。**
> 剧本里有台词、动作、情绪、过场；黑板上只写结论、公式、例子、指令。
> 我之前错把剧本当黑板抄了——老师嘴里说的每一句话我都搬上了屏，导致PPT又长又散，学员盯着满屏字反而抓不住重点。
> 你的改法本质上是在做一件事：**把"老师要说的话"和"学员要看的字"重新分开。**
