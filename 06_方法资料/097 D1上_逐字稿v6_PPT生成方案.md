# 097 ｜ 《Vibe Coding 3天营》D1上午 · 逐字稿 → PPT 生成方案

> 依据：`240 D1上_逐字稿_v6`（7块，90分钟，底稿制）＋「逐字稿→PPT」知识包 ＋ Feishu2slide 机制。
> 本方案可直接执行：页面规划 → 完整脚本表 → 重点页视觉 → 备注映射 → 生成路径 → 质检。

## 0. 一页速览（结论先行）

| 项 | 结论 |
|---|---|
| 总页数 | **52 页**（90 分钟，含封面、6张章节页、封底） |
| 节奏页/内容页 | 节奏页 **22页（42%）** ／ 内容页 **30页（58%）** |
| 为什么节奏页偏高 | 这是**体验驱动课**，80%时间是演示+学员实操。屏幕需要反复"重新聚焦"：任务卡页、锚点页、指令卡页必须占屏停留，页数不能省 |
| 平均停留 | 约 104 秒/页；纯概念页 60–90 秒，任务卡页 240–300 秒 |
| 主稿载体 | **双轨**：飞书幻灯片（协作审校）＋ PPTX（现场交付/离线备份） |
| 核心页型 | 4 类：**演示指令卡**／**结果证据页**／**任务卡**／**名词链单页** |
| 三个关键判断 | ①必说句 ≠ 必上屏，先问"学员要看见还是要听见"；②演示页拆成"指令页—黑屏演示—结果页"三段；③锚点分"上屏锚点条"和"只进备注的自检锚点" |

## 2. 完整页面脚本表（52页）

**源段编码**：`B{块}-{段}`，如 B4-02＝块四第2段。每页可回溯到逐字稿原句。

### 4.1 备注标准模板（每页统一）

```

【锚点】本页涉及的锚点（含时间点）
【口播】必说句（黑体原文，逐字不改）

### 4.2 映射示例一：P04 任务卡（块一）

```

### 4.4 锚点的三种处理方式（7个锚点）

| 锚点类型 | 例子 | 处理 | 理由 |
|---|---|---|---|
| **内容型锚点** | P03"你没写一行代码"、P11"我也能做成这个样子"、P21"你手机里有一个你改过的贪吃蛇"、P44"你不是在学编程，你是在学指挥" | **独立上屏**（锚点页/金句页） | 学员需要"看见"才能记住，是全课的钉子 |

### 4.5 四删四留在这份逐字稿上的落地

#### 核心判断法：必说 ≠ 必上屏

> **必说句要问一句：学员需要"看见"这句话，还是只需要"听见"？**
> 需要看见 → 上屏（标题/大字/卡片）；只需要听见 → 进备注【口播】

例：
- "来，先不急着讲课。" → 必说，但**不上屏**（听见即可）
- "你没写一行代码。" → 必说，**必须上屏**（这是钉子）
- "我点错了，报错也是信息。" → 必说，**不上屏**（进【预案】）

#### 删

| 删什么 | 本稿例子 | 去哪 |
|---|---|---|
| 口语连接词 | "来，""那，""现在，""注意，" | 保留在【口播】原文，但不进标题、不进正文 |
| 重复金句 | "你没写一行代码"在块一、块六各出现一次 | **只上屏一次**（P03），块六出现时进【口播】回扣 |
| 现场自由发挥（＿） | ＿标注的所有内容 | **只留提示词**，不留内容 |
| 无关铺垫 | "我先问大家一个数。"这句引导 | 进【口播】，不上屏（P02 只放四个时间胶囊） |
| 讲师个人叙述 | "我电脑上还存了一份" | 进【预案】 |

#### 留

| 留什么 | 本稿例子 | 上屏位置 |
|---|---|---|
| **结论/必说句** | "提示词不是一次写对的，是越改越好的" | P19 金句页 |
| **数字** | 30秒/3分钟/3小时/3天；20个客户；5斤29.9；今晚8点；80字以内 | P02 四胶囊、P37"30秒"、P27 案例内 |
| **步骤** | 角色+任务+背景+要求+格式；访谈三问式结构 | P24 公式页、P20 任务卡 |
| **对比** | 不会问 vs 会问；第一版 vs 迭代版；公文体 vs 微信体 | P17/P18/P26/P27/P28 |
| **案例冲突** | 贪吃蛇普通→变形；卖苹果万能广告→直接能发 | P16/P17/P26/P27 |
| **金句** | 每块末"只许记住这一句" | P03/P11/P19/P30/P44/P51 |
| **锚点** | 7个锚点 | 见 4.4 分类处理 |

| 压缩比 | 约 **7:1 到 9:1** |
| 单页正文 | ≤5 行，每行 ≤18 字（任务卡页例外，允许整屏文字但必须极简） |

## 5. 生成路径：飞书幻灯片 + PPTX 双轨

### 5.1 载体选择

| 用途 | 载体 | 理由 |
|---|---|---|
| **主稿/协作/审校** | **飞书幻灯片** | 多人批注、改版留痕、和飞书文档打通、状态可追踪 |
| **现场/交付** | **PPTX** | 讲师本机离线、字体嵌入、断网可讲、可导出PDF |
| **学员版** | PPTX/PDF | 删备注、删敏感截图 |
| **离线备份** | 预录 GIF/截图 | 演示失败预案的物理备份 |

**结论：以飞书幻灯片为主稿，导出 PPTX 做现场交付；不做单轨。**

### 5.2 模板建议

**主题**：深蓝星空（呼应成品①"星空海报"，形成课程视觉一致性）。

**三套版式**：

| 版式 | 用途 | 背景 | 字号 |
|---|---|---|---|
| **演示版式** | 封面、章节页、金句页、锚点页 | 深蓝星空渐变 | 标题 48–60pt |
| **讲授版式** | 概念页、对比页、链条图 | 深蓝底 + 浅灰卡片 | 标题 36–44pt，正文 24–28pt |
| **任务卡版式** | 指令卡、任务卡、模板存屏页 | **浅色高对比底**（白/浅灰） | 标题 36pt，正文 28–36pt |

> **关键决策**：任务卡页和指令卡页必须用**浅底**。学员要拍照、抄写、照着打命令，深底在教室投影下会糊成一片。

**字体**：标题思源黑体 Heavy，正文思源黑体 Regular，指令卡等宽字体（JetBrains Mono / 思源等宽），让"可复制"的暗示成立。

**统一元素**：右下角页码+块号（`B4 · 17/52`）；底部锚点条（仅锚点页/自检页）；章节页统一同一张星空底板。

### 5.3 分步执行 SOP（7步，总工期约4.5个工作日）

```
Step 1  逐字稿结构化预处理（0.5天）
        → v6 拆成 B1-B7 段编号

Step 2  生成页面脚本表（0.5天）

        → 录入本方案第2节脚本表
        → 产出：页面脚本表.base

Step 3  主讲审结构（1小时会）

        → 产出：结构定稿

Step 4  生成页面骨架（1天）
        → 飞书幻灯片建 52 页，套三套版式
        → 先只放标题（结论化）+ 核心信息
        → 产出：骨架版.fslide

        → 产出：交付包
```

## 7. 三个最容易踩的坑（针对这份逐字稿）

**坑1：把"必说句"全部上屏。**
这份逐字稿黑体字很多，如果黑体全上屏，会变成 52 页全是字。**记住：黑体只是"必说"，不是"必上屏"。** 用"看见/听见"判断法筛。

**坑2：演示时没有回放页。**
块二、块四、块六、块七都有现场演示。演示时屏幕被豆包/成品占满，PPT 不可见。如果没有 P07/P08/P37/P48 这样的**回放证据页**，学员演示完就忘了，拍照也没得拍。

**坑3：锚点全部上屏。**
"【第8分钟】""【第22分钟】"这类时间锚点是给讲师的自检时钟，上屏会让学员困惑。只有"你没写一行代码""你不是在学编程，你是在学指挥"这种内容锚点才上屏。

---

**一句话总结本方案**：
> 52 页，7 块对应清楚；把原稿的黑体"必说句"按"看见/听见"重筛一遍，把舞台提示、锚点、预案按三种规则映射进备注；三张指令卡、四张回放页、一张名词链总图、一张回扣闭环页，是这份 PPT 的五个支点。主稿用飞书幻灯片，交付用 PPTX，7 步走完，4.5 天可发。
