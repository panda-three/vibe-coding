# 092 演示式教学方法论（课程版AI）

> 来源：课程版AI 对话抓取（2026-09-30）
> 用途：配合 [[091 逐字稿写作方法论]]，专治你的红线「每个名词必配当场演示」＋单人单机无助教场景。
> 一句话：**大屏负责"看见概念"，手机豆包负责"亲手验证一句话"；一概念一演示，每演示必配60秒手机微跟做。**

---

## 1. 核心原则

- 什么算好的当场演示：**现象 → 命名 → 验证**，不是"先定义后演示"（零基础没有锚点，先定义=废话）。
- 演示与讲解：**先演示后解释**；演示≤4分钟，超过必须插"停、看、问"。
- 一概念一演示，一个判断标准；一个演示只解决一个名词。

## 2. 演示完整流程（与 [[091]] 的三件套/五条/四步衔接）

**演示前·预告三件套**（周式口语版）：
1. 痛点/结果："接下来我用一句话做两样东西。"
2. 概念名+目标："看完你们要能说出：我那句话里装了什么。"
3. 观察任务："重点看两件事：我手指只打字；它自己出东西。"

**演示中·五条解说**：意图（我在做什么）→ 操作（我现在打字…）→ 变化（看，出来了）→ 概念（关键在这：我要什么，不写怎么做）→ 边界/错误（如果你只打'做个海报'，它就给你个随便的）。

**演示后·收口四步**：回扣目标 → 一句话概念 → 判断标准/迁移 → 跟做指令。

## 3. 单人单机无助教控场

- 跟做指令四步：打开豆包 → 输入这句话 → 看输出里有没有×× → 完成后抬头。
- 三层任务兜底：**基础版**照抄屏幕Prompt／**进阶版**改一个词／**挑战版**让豆包解释为什么。
- 硬规则：跟做**60秒硬停**，不让少数人拖全场；没做完的只做"观察任务"（看别人结果，回答一个问题）；网络差→看大屏截图+豆包语音输入。
- 兜底话术："没做完没关系，先看我的结果，回头补。"
- 无互动工具时用：举手、抬头、拍桌、齐读回收。

## 4. 手机能复现的演示设计

- 配比：**一次大屏演示配一次手机微跟做**，不要一个演示配多个手机任务。
- 适合全场跟做：提问、追问、改写、对比、判断、让AI解释、拆解、总结（10秒出结果、3步内、失败不影响后续）。
- 只适合看：安装、终端、部署、API、多窗口、复杂调试（手机替代：截图、让豆包解释、列清单）。

**Vibe Coding 名词配对示例**：

| 名词 | 大屏演示 | 手机豆包跟做 | 判断标准 |
|---|---|---|---|
| Prompt | 模糊 vs 具体 | 输入具体工单 | 输出能直接用 |
| 上下文 | 同一对话追问 | 先问电影，再问"第二部呢" | AI记得前文 |
| 幻觉 | 问不存在事实 | 问"鲁迅和周杰伦合作过哪首歌" | 要求给来源 |
| 迭代 | 改一个词看变化 | 把"正式"改成"口语" | 输出语气变了 |
| 调试 | 报错→让AI解释 | 让豆包解释报错文本 | 能说出下一步 |
| 部署 | 大屏展示上线 | 让豆包列部署清单 | 知道"发布"≠"运行" |

## 5. 演示失败预案

- **通用救场三步：承认 → 归因 → 替代。** 话术："正好，这就是真实情况，我们看预案。"不要道歉超5秒。
- 分类预案：

| 故障 | 5秒话术 | 动作 |
|---|---|---|
| 网络断 | "没网也是真实情况，先看缓存图。" | 切截图/录屏，学员手机试 |
| 豆包卡 | "AI也会排队，先看刚才结果。" | 切已生成文本 |
| AI胡说 | "抓到了，这就是幻觉。" | 追问来源，让AI自检 |
| 投屏黑 | "看大屏不行，看手机。" | 切手机投屏/口述步骤 |
| 自己点错 | "我点错了，报错也是信息。" | 快速重来，不纠结 |
| 时间不够 | "这个我录成30秒，课后发。" | 只留结论，跳过细节 |
| 代码报错 | "报错是最好的老师。" | 让豆包解释，当调试演示 |

- **开课前10分钟检查**：网络、电源、投屏、字号、登录、豆包可用、备用热点、录屏、截图、Prompt文本、计时器。

## 6. 最常见的5个坑

1. **先定义后演示**（零基础没锚点）→ 现象→命名→验证
2. **一个演示塞多个概念**（信息过载）→ 一概念一演示
3. **只演示不跟做**（学员以为会了，一拿手机就卡）→ 每演示必配60秒微跟做
4. **手机复现错配**（大屏讲复杂操作却让手机跟做）→ 看/做分离
5. **失败无预案**（翻车就崩）→ 预演失败，把报错/卡顿/幻觉当教学素材

