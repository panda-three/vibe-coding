# 100 香稿转PPT Skill体系设计_v1（1总控 + 3原子）

> 状态：**草案，供评审**。依据：096（逐字稿转PPT方法论+Feishu2slide拆解）、097（D1上生成方案）、098（讲香方法论）、099（复盘沉淀）、099.5（outline-to-transcript Skill设计评估先例）、香稿 v1、脚本表 v2 实战复盘（内容空/字体小/无动画/重叠溢出/Obsidian写坏五类问题）。
> 目标：把"**香稿 → 标注版 → 脚本表 → 深化表 → PPTX**"流水线沉淀为可复用的 Skill 体系，任何课（不限于 Vibe Coding 营）都能跑。

## 一、总体架构

```
                ┌─────────────────────────────────────────────┐
                │         xianggao-to-ppt（总控·编排层）        │
                │  判定输入→调度原子→管理中间产物→验收交付      │
                └──────────────┬──────────────┬───────────────┘
                               │              │
         ┌─────────────────────┼──────────────┼─────────────────────┐
         │                     │              │                     │
   ┌─────▼──────┐      ┌──────▼───────┐   ┌──▼──────────┐    ┌─────▼──────┐
   │ outline-to │      │ xianggao-    │   │ annotate-to │    │ scriptsheet-│
   │ -transcript│      │ annotate     │   │ -scriptsheet│    │ to-pptx     │
   │ （已有）    │──▶   │（原子①）     │──▶│ （原子②）   │──▶ │ （原子③）   │──▶ PPTX
   │ 大纲→底稿  │      │ 香稿→标注版  │   │ 标注→脚本表 │    │ 深化→PPT+验证│
   └────────────┘      └──────────────┘   └─────────────┘    └─────────────┘
        ▲                   ▲                 ▲                    ▲
        │                   │                 │                    │
        │      transcript-to-xianggao（已有：底稿→香稿，可选环节）   │
        └──────────────────────────────────────────────────────────┘
```

**分层逻辑**：
- **总控（1个）**：只做编排与验收，不写内容、不碰渲染。决定走"全流程"还是"只到脚本表"。
- **原子（3个）**：各管一段，输入输出通过**共享协议**对接，可独立复用、独立测试、独立改进。
- **上游复用（不重造）**：`outline-to-transcript`（大纲→底稿）、`transcript-to-xianggao`（底稿→香稿）已存在，总控调用即可。
- **合并判断**：深化表（脚本表→深化表）是纯数据转换、无独立审阅价值 → **并入原子③**；四重验证是生成内置步骤 → **并入原子③**。

**为什么是 1+3 而不是 1 或 6**（复盘结论）：
- 中间产物（标注版/脚本表）是**独立交付物**（用户要求脚本表双交付）→ 必须有关卡 → 拆
- 内容环节（①②）与工程环节（③）**引擎不同**（LLM 生成 vs python-pptx）→ 拆
- 全自动一条龙是翻车温床（源头选错/内容空/重叠溢出均在整链跑时爆发）→ 必须分步确认 → 拆但保持总控编排

## 三、共享协议（三个原子的"通用语言"——必须固化）

> 共享协议是全体系的骨架，改动需在总控登记版本号。以下全部来自本次实战验证。

### 3.1 B 段编码规范（原子①输出）

- 格式：`B{块号}-{序}`，如 `B8-01`（块八第1段）
- 块号与香稿块一致（块八~块十三）；跨块引用写 `B10-17`
- 每段 = 一条可念句/一个舞台提示；同一口播句拆成多条时不改编码
- 去向三层：**上屏**（黑体/斜体核心句）、**口播**（讲师说、不上屏）、**备注**（停顿/备选/舞台提示）

### 3.2 页型枚举（15 种，原子②用）

封面 | 封底 | 章节 | 内容 | 指令卡 | 任务卡 | 提问 | 对比 | 图文 | 存屏 | 金句 | 锚点 | 大字 | 桥 | 行动

每种页型绑定：母版页型映射 + 字号档 + 字数上限（见 3.4）。

### 3.3 脚本表八字段（原子②输出，也是飞书表格列）

| # | 字段 | 约束 |
|---|---|---|
| 1 | 页号 | P01–P50 连续 |
| 2 | 块 | 追溯香稿块 |
| 3 | 页型 | 15 种枚举之一 |
| 4 | 标题 | 结论句，≤30字，超长自动降档 |
| 5 | 核心信息 | 上屏整句，①/②/③=动画击次；指令/模板/案例/金句100%，内容页60% |
| 6 | 上屏字数 | 核心信息总字符数，页型上限内 |
| 7 | 动画分步 | 第N击出现内容 |
| 8 | 备注 | 口播/停顿/备选/舞台（讲师提词卡） |
| 9 | 时长(秒) | 累计≈课时 |
| 10 | 源段 | B段编码 |

（飞书表格版另有冻结首行/斑马纹/列宽规范，见原子② SKILL）

### 3.4 生成规则常量表（原子③执行，全课通用）

| 元素 | 字号 | 说明 |
|---|---|---|
| 页面标题 | 28pt（超1行→24pt） | 结论句≤30字 |
| 正文 | 20pt | 内容/图文页 |
| 指令卡/任务卡 | 22pt | 操作步骤大字 |
| 金句 | 32pt | 单句上屏 |
| 大字页 | 26–32pt | 悬念/结论/锚点 |
| 图注/底部条 | 16pt | 辅助信息 |
| 类型标签 | 16pt | 【思考】【行动】等 |

- **行数估算**：中文字宽=字号×0.95（不是0.55）；行高=字号×1.25/72 英寸
- **字数上限**：内容页≤180字、指令卡≤160字、金句≤35字、大字页≤30字
- **动画**：正文逐段独立文本框+单击淡入（click→delay=indefinite→set visibility→fade 500ms）；提问页先问题后答案；时间线按①/②/③依次；封页/单句金句不带
- **防溢出**：空间不足→紧凑重排（保动画粒度）→仍不足合并最后两段，绝不压扁；question/quote 标题按宽自适应字号（≤2行），正文起点动态下移

### 3.5 母版页型映射（原子③）

封面/封底→slide1｜章节→slide3｜桥/锚点/大字→slide4｜内容→slide5｜图文→slide6｜提问/金句→slide8

### 3.6 验证套件（原子③内置四重）

1. zip 完整性（`zipfile.testzip()`）
2. XML well-formed（逐 .xml/.rels 解析）
3. 占位残留扫描（母版占位关键词）
4. 重叠/溢出校验（`verify_overlap.py` + 行数×行高溢出预警）

### 3.7 交付规范

- **禁止从 Obsidian 打开 .pptx/.docx/.xlsx**（Obsidian 当纯文本写坏：体积膨胀~2倍、`BadZipFile: bad offset`）
- 交付：本地 PPTX + 飞书脚本表双交付；产物 `_vN` 递增，原版保留

## 四、三个原子 Skill 的 SKILL.md 骨架

### 4.1 原子① `xianggao-annotate`（香稿 → 标注版）

```markdown
---
name: xianggao-annotate
description: 把香稿切成"上屏/口播/备注"三层去向的标注版（B段编码），为页面脚本表提供段级编码。
  输入是已完成的香稿（可来自 transcript-to-xianggao），输出是 07_ppt稿/ 下的标注版 MD。
  触发词：标注、Step1、结构化预处理、香稿转标注。
---
# 香稿 → 标注版（B段编码）
## 输入（动手前先读全）
1. 香稿（05_逐字稿/*香稿_vN.md）：全量读块结构/锚点/黑体斜体/舞台提示/备选
2. 本目录 references/标注编码规范.md：B段编码+三层去向规则
3. 先例：grep 项目内"标注版"——有先例先读（如 240 D1上2_香稿标注版_v1.md）
## 工作流
### 第1步 探查（10分钟） 全量读香稿+编码规范+grep先例
### 第2步 逐块切段 每块按小节切段，每段一个 B{块}-{序}
### 第3步 标三层去向
- 上屏：黑体必说句/斜体关键词（可整句或提炼，保留完整句子）
- 口播：讲白/过渡句/自问自答（不上屏）
- 备注：停顿/备选分支/舞台提示/【大屏】动作
### 第4步 页提示 每段预标 page_hint（P01…），与脚本表页号对应
### 第5步 自检
- [ ] 全部香稿段有编码、无遗漏（逐块比对）
- [ ] 黑体句全部落入"上屏"或"金句"
- [ ] 锚点段标注了锚点时间
- [ ] 三回扣句（若有）已落位
### 第6步 交付
- 命名：`{课程}_{段}_香稿标注版_vN.md`（随香稿版本递增）
- 位置：项目 `07_ppt稿/`
- 文件头写：来源/用途/体例/标注schema/页数统计
```

### 4.2 原子② `annotate-to-scriptsheet`（标注版 → 脚本表）

```markdown
---
name: annotate-to-scriptsheet
description: 把香稿标注版切成 50 页级页面脚本表（八字段+字数上限+动画分步），产出可审阅、可上屏的页面契约。
  输入是标注版 MD（来自 xianggao-annotate），输出是本地 MD + 飞书表格双交付。
  触发词：脚本表、页面脚本、Step2、生成脚本表。
---
# 标注版 → 页面脚本表
## 输入
1. 标注版 MD（07_ppt稿/）：全量读 B段编码+去向+page_hint
2. references/脚本表协议.md：八字段schema+页型枚举+字数上限表
3. 先例：grep"脚本表"——先读最近一版（如 240 D1上2_PPT页面脚本表_v2）
## 核心规则（复盘沉淀，不可省）
1. 页型只取 15 种枚举之一，页型决定母版映射+字号档
2. 标题结论化：≤30字，能独立传达信息（不是名词标签）
3. 核心信息整句化：指令/模板/案例/金句 100%；内容页保留约 60% 整句；桥/锚点克制
4. 每页写"上屏字数"并卡页型上限（防溢出/防内容空）
5. 每页写"动画分步"：第N击出现什么（提问先问题后答案、时间线依次）
6. 时长列累计≈课时（90分钟课配 75–80 分钟脚本+缓冲）
## 工作流
### 第1步 探查（读全）标注版+协议+先例
### 第2步 定页面骨架 按块分页（约6-12页/块），页型分配
### 第3步 逐页填八字段（表格式产出）
### 第4步 时长核算 累计时长≈课时，超出的页削或并入
### 第5步 双交付
- 本地 MD：`07_ppt稿/{课程}_{段}_PPT页面脚本表_vN.md`
- 飞书表格：+workbook-create（冻结首行/斑马纹/表头样式/列宽）→ 回读验证 → present_files 双交付
### 第6步 请用户审阅确认 → 确认后才进原子③（内容契约先行）
```

### 4.3 原子③ `scriptsheet-to-pptx`（深化表 → PPTX + 验证）

```markdown
---
name: scriptsheet-to-pptx
description: 把确认后的脚本表转成整句深化表，再用母版+python-pptx 生成大屏演示版 PPTX：
  字号体系+逐段动画+布局兜底+四重验证。输出本地 PPTX（_vN 递增）。
  输入是脚本表（来自 annotate-to-scriptsheet），输出是 07_ppt稿/ 下的可放映 PPTX。
  触发词：生成PPT、出PPT、PPT骨架、深化表、落屏。
---
# 脚本表 → 深化表 → PPTX
## 输入
1. 已确认的脚本表（MD 或飞书表格）：全量读 50 页八字段
2. 母版：项目 `07_ppt稿/课程PPT母版.pptx`（只读）
3. references/版式与动画规则.md：字号/动画/防溢出/母版映射常量
4. 素材：页型所需的成品截图（真图占位，上课前替换）
## 工作流
### 第1步 生成深化表（脚本表→整句深化表）
- 格式：`### PXX｜页型｜标题` + `- ` 正文（①/②/③ 拆行） + `> 底部：` + `> 副标题：`
- 每页核心信息扩成可上屏整句（不含语气词，保留 60%+ 信息）
### 第2步 渲染（pptx_builder.py）
- 克隆母版对应页型 → set 标题/正文/图/底部条 → 逐段独立文本框
- 按字号体系落字号；按动画分步写 <p:timing> 单击淡入
- 布局兜底：行数估算（0.95宽/1.25行高）→ 空间不足紧凑重排 → 仍不足合并
### 第3步 四重验证（verify_pptx.py + verify_overlap.py）
- zip 完整性 / XML well-formed / 占位残留=0 / 重叠溢出=0
- 动画统计：动画页数+目标数（封页/单句金句除外）
### 第4步 交付
- 命名：`{课程}_{段}_PPT骨架_vN.pptx`（随版本递增，原版保留）
- 交付说明：验证结果+打开方式（勿从 Obsidian 打开）+素材待替换清单
```

## 五、原子③的工程抽象（pptx_builder.py 通用化清单）

> 现状：`240 D1上_PPT生成_脚本_v4.py` 为 D1 上定制（硬编码解析格式/页型布局/字号常量）。复用前必须抽象：

| 项 | 抽象方式 |
|---|---|
| 数据源 | 输入统一为"深化表 MD 协议"（### PXX｜页型｜标题 + `- `正文 + `> 底部/副标题`），不再绑定具体课 |
| 页型布局 | 15 种页型 → 布局参数表（坐标/宽高/字号/对齐）移入 references，脚本按页型查表 |
| 字号体系 | 常量表（§3.4）从脚本抽到 references，可覆盖 |
| 动画生成 | 按"动画分步"列自动生成 timing XML（现有实现保留，抽象为通用函数） |
| 母版 | 页型→slideN 映射表（§3.5），母版路径可配置 |
| 验证 | verify_overlap.py 通用化（参数化页宽高）；verify_pptx.py 合并四重检查 |

**验收标准**：换一门课（如 D3 上），只改"深化表+母版+素材"，脚本零改动或仅改常量表 → 抽象成功。

## 六、总控 `xianggao-to-ppt` 编排逻辑

```markdown
---
name: xianggao-to-ppt
description: 编排"香稿→PPT"全链路：判定输入→调用原子①②③→管理中间产物→验收交付。
  支持三种模式：full（全流程）/ to-scriptsheet（只到脚本表）/ to-pptx（已有脚本表直接出PPT）。
  触发词：香稿转PPT、按香稿出PPT、走一遍流程。
---
# 香稿 → PPT（编排总控）
## 模式判定
- 输入只有香稿 → full：①→②→③
- 输入香稿+只要脚本表 → to-scriptsheet：①→② 止
- 输入已确认脚本表 → to-pptx：②跳过，直接③（先问：深化表有没有？没有则②产出脚本表再确认）
## 编排规则
1. 每步产物命名 `_vN` 递增，原版保留；中间产物留在 07_ppt稿/
2. ②完成后**必须等用户确认**再进③（内容契约先行，防整链返工）
3. ③生成后跑四重验证，验证不过不交付
4. 上游可选：无香稿时调用 transcript-to-xianggao（底稿→香稿）；无底稿时调用 outline-to-transcript
5. 交付物清单：标注版 MD + 脚本表（MD+飞书）+ PPTX，一次交付说明写清路径
## 验收清单
- [ ] 标注版：香稿全段有编码
- [ ] 脚本表：字数/动画/时长齐，用户已确认
- [ ] PPTX：四重验证过，页数=脚本表页数
- [ ] 素材占位已列清单（上课前替换）
```

## 七、与周边 Skill 的边界

| Skill | 定位 | 关系 |
|---|---|---|
| `outline-to-transcript` | 大纲→底稿逐字稿 | 上游，总控可选调用 |
| `transcript-to-xianggao` | 底稿→香稿（五香） | 上游，总控可选调用 |
| 本体系（1+3） | 香稿→PPT | 从香稿出发的"后半链路" |
| `course-co-creation` | 旧课件→换皮→动画→试讲迭代 | **另一条出发线**（已有课件而非香稿）。两体系产物可互用：本体系的脚本表可交给它做动画/备注迭代；不合并、各自独立 |
| `ppt`（飞书幻灯片） | 在线幻灯片读写 | 若交付飞书幻灯片，由总控在③后桥接 |

## 八、安装与验收步骤（评审通过后执行）

1. **先建共享协议**：`references/标注编码规范.md`、`脚本表协议.md`、`版式与动画规则.md`（从本文 §三 摘出细化）
2. **再写三个原子 SKILL.md**（§四骨架补全）
