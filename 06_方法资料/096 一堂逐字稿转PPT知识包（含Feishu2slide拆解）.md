# Part A ｜ 一堂式「逐字稿→PPT」转化知识包

## A0. 总框架：先把链路说清

### A0.1 一句话定义

逐字稿不是PPT，逐字稿是**教学意图的原始矿**；PPT不是讲稿复刻，是**学员的认知脚手架**。转化的本质是：

> 把"讲师说了什么"，转成"学员要看见什么、记住什么、做什么"。

### A0.2 总链路

```text
输入层：逐字稿 + 课程目标 + 学员画像 + 时长 + 品牌模板 + 素材
  ↓
阶段1 预读标注：标出目标、观点、案例、数据、互动、行动、过渡
  ↓
阶段2 结构切块：模块→章节→知识点→页
  ↓
阶段3 页面脚本：一页一认知任务，写标题、正文、视觉、备注
  ↓
阶段4 文字提炼：四删四留，标题即结论，正文即证据
  ↓
阶段5 视觉设计：图表、版式、层级、动画
  ↓
阶段6 讲师备注：把删掉的口语、故事、提醒放回备注
  ↓
阶段7 质检交付：目标、逻辑、文字、视觉、版权、时长、版本
  ↓
输出层：主讲版PPT + 学员版PPT + 讲师备注版 + PDF + 素材包 + 质检单
```

### A0.3 角色分工

| 角色       | 职责              | 关键产出           |
| -------- | --------------- | -------------- |
| 主讲/内容专家  | 定目标、审观点、确认案例、保真 | 课程目标、案例授权、终审   |
| 课程设计师/教研 | 标注、切块、脚本、备注     | 标注稿、结构大纲、页面脚本表 |
| PPT设计师   | 视觉转译、图表、排版      | PPT初稿、视觉规范     |
| 质控/项目    | 查漏、对时、版本、交付     | 质检单、成品包        |

### A0.4 三条铁律

1. **不按口播段落分页，按认知任务分页。**
2. **标题即结论，正文即证据。**
3. **删掉的话进讲师备注，不丢信息。**

### A0.5 四套标准

| 标准 | 核心问题 | 通过线 |
|---|---|---|
| 结构标准 | 这页解决什么认知任务？ | 一页一个任务 |
| 文字标准 | 删掉后影响理解吗？ | 不影响就删 |
| 视觉标准 | 3秒看懂主题吗？10秒看懂结构吗？ | 一视觉中心 |
| 教学标准 | 学员认知变化是什么？行动是什么？ | 可复述、可行动 |

### A0.6 颗粒度总表

| 层级 | 时长/数量 | 判断标准 |
|---|---|---|
| 模块 | 15-30分钟 | 解决一个完整问题 |
| 章节 | 5-10分钟 | 解决一个子问题 |
| 页 | 1-3分钟 | 一个认知任务 |
| 元素 | 标题/正文/图/备注 | 标题≤20字，正文≤5行，图1中心 |
| 文字压缩比 | 逐字稿:PPT正文 ≈ 10:1到20:1 | 1万字逐字稿→500-1000字正文 |
| 页数参考 | 60分钟课程约30-50页 | 结构页20-30%，内容页70-80% |

## A1. 输入层：逐字稿不是PPT，是素材库

### A1.1 输入清单

转化前必须拿到：①逐字稿（最好带时间码、说话人、段落）；②课程目标；③学员画像；④时长；⑤品牌模板；⑥素材（案例/数据/截图/版权）；⑦讲师风格。

### A1.2 预读标注法

不要一上来就打开PPT。先做"逐字稿标注版"：

| 符号 | 含义 | 例子 |
|---|---|---|
| G | 课程目标 | "今天你要学会……" |
| K | 核心观点 | "访谈不是找答案，是找证据" |
| C | 案例 | "有个SaaS团队……" |
| D | 数据 | "20个人里18个说会用" |
| Q | 金句 | "不要问未来，要问过去" |
| I | 互动 | "大家想一下……" |
| A | 行动 | "回去先做一张行为证据表" |
| T | 过渡 | "讲完这个，我们看下一个" |

标注完要能一眼看出：哪些必须上PPT？哪些只适合口述？哪些可删？哪些案例细节进备注？

---

## A2. 结构层：从时间流到教学流

### A2.1 切块逻辑

```text
模块 → 章节 → 知识点 → 页 → 元素
```

切块依据不是"讲了多久"，而是"学员要完成什么认知动作"：

| 认知动作 | 对应页面类型 |
|---|---|
| 引起注意 | 封面、痛点页、问题页 |
| 建立概念 | 定义页、模型页 |
| 证明观点 | 数据页、案例页、引用页 |
| 教方法 | 步骤页、流程图、清单页 |
| 做对比 | 左右对比、前后对比、错误/正确 |
| 促行动 | 练习页、行动页、总结页 |

### A2.2 页面怎么定

```text
总页数 ≈ 内容页 + 结构页
内容页 ≈ 有效讲授时长(min) ÷ 每页平均停留(min)
结构页 ≈ 总页数 × 20%-30%
```

| 课程时长 | 内容页 | 结构页 | 总页数 |
|---|---|---|---|
| 30分钟 | 15-20 | 5-8 | 20-28 |
| 60分钟 | 30-40 | 8-12 | 38-52 |
| 90分钟 | 45-60 | 12-18 | 57-78 |

**判断标准：一页只能回答一个问题**——这页要让学员知道什么？相信什么？做什么？两个以上答案就拆页。

## A3. 内容层：文字取舍与标题

### A3.1 四删四留

**删**：①口语连接（那么、然后、其实）；②重复表达；③自我修正；④无关故事。
**留**：①结论；②数字；③步骤；④对比；⑤案例冲突；⑥金句。

### A3.2 标题即结论

- 错误标题：`用户访谈` → 正确标题：`用户访谈：不要问未来，要问过去`
- 错误标题：`转化率问题` → 正确标题：`转化率低的3个真因：需求错位、信任不足、路径过长`

**判断标准**：标题读给学员听，能不能直接获得结论？不能就重写。

### A3.3 正文颗粒度

- 标题≤20字；正文≤5行、每行≤18字；一页一个观点；数据标来源；能图不文，能表不段，能流程不列表。

### A3.4 讲师备注

删掉的口语、故事、提醒、过渡全部进备注，分段：【开场】【案例细节】【提醒】【过渡】。

### A3.5 案例对照（逐字稿片段 → PPT页面）

**案例1：纠错页** — 逐字稿讲"PPT第一原则是服务认知"，对应PPT页：标题`一页只讲一件事`，正文左右对比（错误：一页塞5个观点 / 正确：一页一个观点标题即结论），备注保留原话。删"很多人以为""其实不是"；留结论；语气铺垫进备注。

**案例2：数据页** — 逐字稿讲"60分钟课程PPT超过80页回忆率下降"，对应页：标题`60分钟课程，30-50页最利于消化`，视觉用横向仪表盘标80+红区/30-50绿区，备注保留"翻页器表演"原话。

**案例3：步骤页** — 逐字稿给五步法，对应页：标题`逐字稿转PPT五步法`，五步流程箭头＋第3步前红色警示"不要打开PPT软件"。

---

## A4. 视觉层：从信息到认知

### A4.1 判断标准

3秒看懂主题 / 10秒看懂结构 / 30秒看懂细节 / 一页一个视觉中心 / 颜色≤3主色、字体≤2种 / 对齐留白对比重复。

### A4.2 图表选型

| 内容关系 | 视觉形式 |
|---|---|
| 流程/步骤 | 箭头、时间轴、流程图 |
| 对比 | 左右、前后、A/B |
| 数据 | 柱状、折线、饼图、仪表盘 |
| 模型 | 矩阵、金字塔、循环图 |
| 案例 | 截图、照片、对话气泡 |
| 清单 | 卡片、图标+短句 |
| 金句 | 大字+留白 |

### A4.3 版式规范

标题区顶部1/5；正文区中部3/5；品牌区底部1/5；留白≥30%；动画只引导注意力不炫技。

---

## A5. 质检与交付层

### A5.1 质检清单（10项）

每页服务课程目标 / 一页一认知任务 / 标题即结论 / 正文≤5行每行≤18字 / 数据有来源 / 案例有授权 / 颜色≤3字体≤2 / 讲师备注完整 / 页数匹配时长 / 主讲版·学员版·PDF分版本。

### A5.2 版本管理

主讲版（含备注动画数据源）/ 学员版（删备注敏感数据）/ PDF版 / 素材包 / 版本号命名：`课程名_v1.2_2025-06-01_主讲版`。

---

## A6. 完整案例：5分钟逐字稿 → 6页PPT

**原始逐字稿**（用户访谈，约200字）→ **页面脚本表**：P01封面`用户访谈：从找答案到找证据`→ P02原则`访谈不是验证想法`→ P03对比`问未来vs问过去`→ P04案例`20人说会用，3人真用`→ P05方法`访谈三问法`→ P06总结`访谈不是找答案，是找证据`。

**每页要素**：标题（结论化）＋正文（≤5行）＋视觉（左右对比/数据图/三卡片/金句大字）＋备注（开场提问/停顿提醒/案例细节/收口行动）。

---

## A7. 常见错误与避坑（8条）

| 错误 | 后果 | 修正 |
|---|---|---|
| 逐字稿直接复制到PPT | 字太多，学员不看 | 四删四留 |
| 先找模板后填内容 | 内容被模板绑架 | 先写页面脚本 |
| 一页多观点 | 一个都记不住 | 一页一认知任务 |
| 标题名词化 | 没有结论 | 标题即结论 |
| 正文段落化 | 阅读负担重 | 短句+图表 |
| 视觉抢戏 | 注意力分散 | 一视觉中心 |
| 备注丢失 | 讲师讲不回细节 | 删掉的话进备注 |
| 页数失控 | 翻页器表演 | 按停留时间定页数 |

# Part B ｜ Feishu2slide 机制拆解（可复制参考实现）

> 说明：YAI 课程版AI 明确声明"没有一堂内部未公开的 Skill 名称、私有飞书 API 权限和真实课程数据"。以下是一套按"飞书文档/妙记逐字稿 → 飞书幻灯片/PPT"还原的可复制参考实现，`feishu2slide.*` 为方便落地设计的命名，可替换成内部叫法。

## B1. 定位与产物

**Feishu2slide = 把飞书里的课程逐字稿/妙记记录，通过"标注 → 切块 → 页面脚本 → 视觉映射 → 生成飞书幻灯片 → 审校导出"流水线，变成可讲、可看、可行动的幻灯片成品。**

输入：飞书妙记转写稿 / 飞书文档逐字稿 / 录音 / 课程目标 / 素材。
输出：飞书幻灯片主稿 + PPTX主讲版 + 学员版 + 讲师备注版 + 页面脚本多维表格 + 素材包 + 质检单。

核心原则5条：不按口播段落分页 / 标题即结论正文即证据 / 删掉的话进备注 / 先写页面脚本再打开PPT / 飞书幻灯片是协作主稿，PPTX/PDF是交付副本。

## B2. 完整工作流（11阶段）

```text
[输入] 飞书妙记 / 飞书文档 / 录音
  ↓ 1 采集入湖 → 2 清洗转写 → 3 教学标注 → 4 结构切块 → 5 页面脚本
  ↓ 6 标题结论化 → 7 视觉映射 → 8 备注回填 → 9 生成飞书幻灯片 → 10 人工审校 → 11 导出交付
[输出] 飞书幻灯片 + PPTX + PDF + 学员版 + 备注版 + 素材包 + 质检单
```

| 阶段 | 工具/能力 | 判断标准 | 人工参与 |
|---|---|---|---|
| 1 采集 | 飞书妙记、飞书文档、开放平台 | 时间码完整、说话人可区分 | 低 |
| 2 清洗 | 豆包AI + 术语表 | 原意不变、术语统一 | 中 |
| 3 标注 | 豆包 + transcript_annotator | 每段标签≤3，不漏核心 | 中 |
| 4 切块 | chunk_builder | 一页一认知任务 | 高 |
| 5 页面脚本 | slide_script_writer + 多维表格 | 每页有标题正文视觉备注 | 高 |
| 6 标题结论化 | title_conclusionizer | ≤20字，读完有结论 | 中 |
| 7 视觉映射 | visual_mapper | 3秒看懂主题 | 中 |
| 8 备注回填 | notes_backfiller | 讲师能讲回细节 | 中 |
| 9 生成 | 飞书幻灯片API/PPTX生成 | 版式统一、可编辑 | 低 |
| 10 审校 | 主讲/设计/质控 | 质检清单全过 | 高 |
| 11 交付 | 飞书云文档、导出 | 版本清晰、权限正确 | 中 |

## B5. 关键设计：逐字稿怎么被结构化

### B5.1 标注 JSON Schema

```json
{
  "source_id": "docx_xxx",
  "title": "用户访谈逐字稿",
  "segments": [
    {
      "id": "s001", "start": "00:00", "end": "00:12", "speaker": "讲师",
      "text": "今天讲用户访谈。第一，访谈的目标不是验证你的想法。",
      "tags": ["G", "K"], "module": "用户访谈", "chapter": "原则", "page_hint": "P01"
    }
  ]
}
```

### B5.2 页面脚本 JSON Schema

```json
{
  "page": 4, "type": "案例页",
  "title": "20人说会用，3人真用",
  "core": "问未来会失真，问过去才可靠",
  "body": ["SaaS团队问20个客户：会不会用新功能？", "18人说会用", "上线后只有3人用", "原因：问的是未来，不是行为"],
  "visual": {"layout": "左右对比+数据图标", "left": "20人图标18绿", "right": "3人图标3绿", "arrow": "未来失真"},
  "notes": "讲案例细节：不是用户撒谎，是问题错了。停2秒。",
  "duration_sec": 150,
  "source_segments": ["s008", "s009", "s010"]
}
```

### B5.3 核心提示词模板（可直接复制）

**总控系统提示词**：

```text
你是 Feishu2slide 课程设计系统。你的任务是把逐字稿转成飞书幻灯片页面脚本。
规则：
1. 不按口播段落分页，按认知任务分页。
2. 标题即结论，标题≤20字。
3. 正文≤5行，每行≤18字。
4. 一页一个观点，一页一个视觉中心。
5. 删掉的口语、故事、提醒放入 notes。
6. 数据必须保留来源或样本说明。
7. 输出严格 JSON，不要输出解释。
```

**标注提示词**：按 G/K/C/D/Q/I/A/T 标注，不改写原文，每段标签≤3，输出 JSON。
**切块提示词**：模块→章节→页，一页一认知任务，页数=有效讲授分钟÷1.5，每页标 source_segments。
**脚本提示词**：标题即结论≤20字，正文≤5行，含 type/title/core/body/visual/notes/duration_sec/source_segments。
**标题结论化提示词**：名词标题→结论标题，≤20字，不标题党。示例：用户访谈→用户访谈：不要问未来，要问过去。
**视觉映射提示词**：一页一视觉中心，颜色≤3字体≤2，能图不文，输出 layout/元素/图表类型/图标。
**备注回填提示词**：把删除的口语故事提醒过渡放入对应页notes，分段【开场】【案例细节】【提醒】【过渡】，不增加新事实。
**质检提示词**：按8项检查输出问题清单和修改建议。

## B6. 自动化实现要点

- **飞书文档采集**：`open.feishu.cn/open-apis` → tenant_access_token → docx/v1/documents/{token}/blocks。
- **妙记采集**：有开放能力用API；权限不可用走"妙记→导出文字→上传飞书文档"半自动路径。
- **豆包调用**：Ark SDK，`response_format={"type":"json_object"}` 强制 JSON 输出。
- **多维表格状态机**：字段＝页码/页面类型/标题/核心信息/正文/视觉建议/讲师备注/时长秒/源段/状态/负责人；状态流转 待标注→待脚本→待生成→待审校→已交付，配合飞书自动化触发豆包工作流。
- **PPTX生成**：python-pptx 套模板，每页写 notes。
- **上传飞书云文档**：drive/v1/files/upload_all。
- **中转路径**：企业未开通飞书幻灯片OpenAPI时，走"PPTX生成→上传云文档→飞书幻灯片打开/转换"。

# Part C ｜ Feishu2slide 系统深拆（知识库+Agent+测试集）

> 依据：本地知识库一手线索（AI教育课·02热身课笔记 + 双三角画布）回喂课程版AI后的深拆。凡标注【线索】是原话；【推断】是基于线索和工程常识补的实现细节。

## C0. 先破一个题：为什么前面所有工具都失败？

线索："反复试国内工具/SlideV/Gamma/NotebookLM都放弃"。不是工具不行，是**这些工具只卖"渲染能力"，不卖"教学判断力"**。

| 工具 | 它优化什么 | 它缺什么 |
|---|---|---|
| SlideV | Markdown→幻灯片渲染 | 不懂"这页该不该有标题结论" |
| Gamma | 一键生成好看的卡片 | 不懂"任务卡页必须浅底大字号" |
| NotebookLM | 资料问答、生成大纲 | 不懂"一堂的锚点、金句、预案" |
| 国内在线PPT | 模板套用 | 不懂"演示页要留回放页" |

一堂的关键转变，是把这些判断力**从人脑搬进了知识库**：

```
失败阶段：人肉判断 → 用工具渲染 → 每次重讲一遍标准
成功阶段：知识库存判断 → Agent执行判断 → 测试集校验判断
```

> **Feishu2Slide 不是"用AI做PPT"，是把"一堂做PPT的judgment"代码化 + 资产化 + 自动迭代化。**

## C1. 三角：知识库 + Agent + 测试集

| 组件 | 回答的问题 | 失败时会怎样 |
|---|---|---|
| 知识库 | "什么是对的？" | Agent每次都自由发挥，质量漂移 |
| Agent（Hermes） | "怎么做到？" | 知识库躺在那里没人用，还是人肉做 |
| 测试集 | "做得好不好？" | 改了Agent不知道变好变坏，不敢迭代 |

**闭环**：`知识库 → 喂给Agent → 产出成品 → 测试集打分 → 反馈 → 更新知识库`。这是"无天花板"的机制根源：边际成本递减、质量不崩、系统自进化。

### C1.1 知识库怎么配

载体选 **Obsidian**（双向链接/本地存储/Git版本管理/Agent直接读文件），飞书存协作流程，两者分工。目录结构：

```text
feishu2slide-kb/
├── 00-索引/          # MOC-总览/内容线/视觉线/质检线
├── 10-模板库/        # 演示版式/讲授版式/任务卡版式 + 模板源文件
├── 20-排版策略集/    # 内容-版式映射表/一页一认知任务判定/标题结论化/正文提炼
├── 30-配图指南/      # 何时配图/配什么图/图表选型/素材规范
├── 40-判断力案例库/  # 好案例-逐字稿到PPT对照/坏案例-常见错误/争议案例
├── 50-测试集/        # test-cases/expected-outputs/scoring-rubric
├── 60-复盘/          # 复盘模板 + 历次复盘
└── 90-提示词库/      # annotate.md script.md ...
```

**关键原则：知识库里放的不是"最终答案"，是"判断依据"。** 比如不放"P04应该是任务卡页"，而放：

> 判断规则：当逐字稿出现【动作】让学员操作 + 停顿≥60秒 + 无新知识时 → 页面类型=任务卡 → 版式=浅底高对比 → 字号≥28pt。

这样 Agent 才能举一反三。

### C1.2 Hermes Agent 怎么配

"Hermes"（信使神）暗示角色：**在知识库和产出物之间传递消息，在人和Agent之间传递任务**。做五件事：读任务（飞书多维表格）→ 查知识库 → 调 Skill → 写产出 → 写日志。

与普通Agent区别：知识来源=外部知识库（可持续增长）；记忆=不依赖Session靠复盘文件；输出=可校验的结构化产物；迭代=改知识库+改测试集而非改提示词。

**Hermes 很可能不是"一个大Agent"，而是"编排骨架 + N个专职Skill"**——这就解释了为什么是"10个Agent"。

### C1.3 测试集怎么配（最关键的组件）

**测试集 = 一组"输入-期望输出"对照样本 + 一套评分标准。**

```
test-cases/case-01-用户访谈/
├── input.md              # 2000字逐字稿
├── expected-pages.json   # 期望的8页脚本
├── expected-notes.json   # 期望的备注
└── human-score.md        # 人工评分
```

**评分项 Rubric（测试集的灵魂）**：

| 维度 | 权重 | 自动化方式 |
|---|---|---|
| 标题结论化率 | 20% | 关键词/句式检测 |
| 页数合理性 | 15% | 公式计算 |
| 任务卡识别率 | 15% | 检测停顿+动作标记 |
| 锚点保留率 | 15% | 关键词匹配 |
| 正文合规率 | 15% | 规则校验 |
| 备注完整率 | 10% | 正则匹配 |
| 视觉合理性 | 10% | 规则校验 |

它把"我觉得改好了"变成"评分从72涨到85"——从手工作坊到工厂的分水岭。**这也是为什么前面试工具都失败而这次成功——这次有了一把尺子。**

## C2. 三资产库：模板库 / 排版策略集 / 配图指南

```
模板库     → 资源层（可复制的结构）
排版策略集 → 规则层（内容→版式的决策逻辑）
配图指南   → 素材层（何时配图、配什么图）
```

### C2.1 模板库：装"版式的物理形态"

每个模板 = 一个`.pptx`母版 + 一份`.md`描述文件（YAML 规格书：使用场景/版式/约束/示例页面）。Agent 拿到的不是一张图，是**一份可执行、可校验的规格书**。

### C2.2 排版策略集：装"什么内容配什么版式"的决策规则（判断力载体）

**表1：内容类型→页面类型映射**

| 逐字稿信号 | 页面类型 | 版式 |
|---|---|---|
| 黑体必说句+无动作 | 金句页 | 演示版式（大字） |
| 【动作】+停顿≥60秒 | 任务卡页 | 任务卡版式 |
| 有"错误/正确"结构 | 对比页 | 对比版式 |
| 有数字+比例 | 数据页 | 数据版式 |
| "上一个做不到→下一个" | 名词页 | 名词链版式 |
| 演示前：可复制指令 | 指令卡页 | 任务卡版式 |
| 演示后：截图结果 | 结果证据页 | 讲授版式（满屏图） |
| 章节切换 | 章节页 | 演示版式 |

**表2：结构判断规则**：不按口播段落分页；一页只回答一个问题；演示页永远三段式（指令页→黑屏演示→结果页）；演示后必须有回放页；60分钟课30-50页（体验驱动课可到55页）；每块必须有收束。

**表3：标题结论化规则**：名词标题→结论标题（提示词→提示词：你发给它的那句话）；例外：悬念页允许保留问句。

**表4：文字取舍规则（四删四留）** + 判断法：必说≠必上屏，需要"看见"→上屏，只需"听见"→进备注。

**沉淀方式**：不是一次性写完，是每次复盘时增量沉淀（发现→原因→修订→写入策略集→下次自动生效）。

### C2.3 配图指南：装"何时配图、配什么图、怎么配"

何时配图（概念/流程/数据/对比配，金句/锚点不配）；图表选型表；AI作图框架（示意图用豆包生图、数据图用代码、截图从素材库调取、风格用统一提示词模板）；配图规范（一页一视觉中心/颜色≤3/留白≥30%/版权状态）。

**复用关键＝风格模板化**：一个课程风格定下来，所有图提示词后段都一样只换主体，保证1000页视觉一致。例：`"…，极简扁平，深蓝星空主题，无文字，16:9"`。

### C3.3 并行与"1000页无天花板"

### C4.3 搭建步骤

**Step 0 建测试集（先建尺子）**：挑3个已完成好课程（如 Vibe Coding D1 块一/块四/块六），每个课做 输入逐字稿→期望页面脚本JSON→Rubric评分→人工基准分。
**Step 1 建知识库骨架**：Obsidian 建 10-模板库/20-排版策略集/30-配图指南/50-测试集，每个文件最小10-20行规则。

**Step 3 写3个核心Skill**（Annotate/Script/Build 系统提示词见 B5.3）。
**Step 4 跑一个真实课程验证**（Vibe Coding D1 块一5页跑通：录入→建5行→待标注→Annotate→人工审→待脚本→Script→人工审→待生成→Build→5页PPTX→测试集评分→记录得分）。
**Step 5 第一轮复盘**：哪些页做对了？哪些错了为什么？错的规则加进知识库哪里？写完复盘文件更新知识库——这一步做完就有了能自我进化的最小系统。
**Step 6 扩到10Agent/3人**。

### C4.4 MVP 边界（诚实声明）

能做：结构清晰的逐字稿→页面脚本 / 标准课型 / 单课跑通 / 规则内判断 / 提示词级自动化。
做不到：高度即兴对话→脚本 / 全新课型 / 多课并行（需Hermes编排）/ 规则外教学创新 / 完整Agent自主迭代。

## C5. 从MVP到"3人+10Agent无天花板"的演化路径

| 级别 | 特征 | 能力 |
|---|---|---|
| L0 手工 | 人做PPT | 一次一课 |
| L1 提示词 | 用GPT辅助 | 提速2倍 |
| L2 MVP | 3个Skill | 跑通闭环 |
| L3 系统 | 10Agent+知识库+测试集 | 多课并行 |
| L4 自进化 | AI自动复盘+知识库自增长 | 质量不崩 |

L2→L3：补齐10Agent / 3资产库 / ≥10案例测试集 / Hermes编排。
L3→L4：每次交付后自动Retro / 复盘自动归库 / 每月知识库合并 / 测试集扩充。
L4→L5：新规则自动A/B测试 / 高分规则自动上线 / 人类只做元判断。

## C6. 一张图总结

```
为什么前面失败？ → 只买了"渲染工具"，没买"判断力"

```

```text

这页需要几分钟？
```

## 一句话记住本知识包

> 逐字稿转PPT，不是"把话搬上去"，而是"把讲授流切成认知任务，把认知任务写成结论标题，把结论配上证据视觉，把细节放进讲师备注，最后用质检保证可讲、可看、可行动"。Feishu2slide 则是把这一整套判断力装进知识库、执行力装进Agent、衡量力装进测试集，让系统自进化。
