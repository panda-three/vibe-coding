# 013 AI 智能体第一课·知识包

> 来源：YAI 课程版AI 对话抓取（conversation: 07469daf-21c1-41bd-9ef6-1b2d5fa6f8ff，2026-09-30）
> 课程归属：一堂正课（AI 产品/技术系列）
> 用途：作为本营课程案例设计的「方法论底座」，案例内容与 AI 智能体第一课方法论深度镶嵌

> 定位为产品/技术/运营通用的 Agent 搭建、工具调用与业务集成方法论底座。

## 一、课程定位与目标

**定位**：Agent 入门到业务集成的正课。不是讲大模型原理，而是讲"如何把 LLM 变成能办事的业务系统"。

**一句话主线**：从"会聊天"到"能办事"，核心公式为：
**Agent = LLM + 规划 + 记忆/RAG + 工具调用 + 业务系统 + 治理评估**

**目标**：
- 认知：分清 Chatbot、Workflow、Agent 的边界，知道何时该用、何时不该用 Agent。
- 方法：掌握 Agent Loop、任务规划、工具契约、RAG/记忆、业务集成、评估与安全治理。
- 产出：能设计一个可落地 Agent 方案，含场景、流程、工具、数据、权限、指标、上线路径。
- 协作：产品定义价值与流程，技术实现集成与可靠性，运营反馈调优与持续运营。

## 二、核心方法论/模型

### 1. 五层架构
- 交互层：入口、多轮对话、表单、消息渠道。
- 编排层：Planner、Router、Policy、任务分解、重规划。
- 能力层：工具、API、RAG、数据库、记忆、外部系统。
- 执行层：动作执行、工作流触发、工单、CRM、订单、审批。
- 治理层：权限、审计、脱敏、风控、人审、灰度、评估。

### 2. 三闭环
- 任务闭环：目标 → 计划 → 工具调用 → 观察 → 反思/重规划 → 输出/行动。
- 数据闭环：Trace → 评估 → Badcase → Prompt/工具/知识优化。
- 业务闭环：业务指标 → 上线灰度 → 人工协同 → 复盘迭代。

### 3. 四阶段落地
选场景 → 搭 MVP → 接工具/系统 → 上线运营。

### 4. 核心运行模式
- ReAct：推理 + 行动交替。
- Plan-and-Execute：先规划再执行，适合复杂任务。
- Reflexion：失败后反思重试。
- Router：按意图路由到不同工具、知识库或子 Agent。
- 多智能体：仅在角色分工明确、收益大于复杂度时使用。

### 5. 工具调用三件套
- 工具契约：名称、描述、参数 Schema、返回结构。
- 权限控制：身份、范围、鉴权、审计。
- 可观测：调用日志、成功率、延迟、成本、错误码。

### 6. 业务集成原则
API 优先、事件驱动、人审兜底、灰度上线、可回滚、可追踪。

## 三、关键知识模块

| 模块 | 关键要点 | 产出物 |
|---|---|---|
| 场景与边界 | 高频、规则清晰、有数据、有工具、容错可接受 | 场景卡、价值判断 |
| 任务规划与编排 | 分解、路由、重试、终止条件、异常处理 | 任务流图、Agent Loop |
| 记忆/RAG | 短期上下文、长期记忆、知识库、检索质量 | 知识源清单、RAG 策略 |
| 工具调用 | Function Calling、MCP、OpenAPI、参数校验、幂等 | 工具清单、API 契约 |
| 多智能体 | 角色、通信、仲裁、成本控制 | 协作拓扑、何时不用 |
| 评估与可观测 | 成功率、工具准确率、成本、延迟、安全 | 指标看板、Trace |
| 安全治理 | 提示注入、越权、泄露、合规、人审 | 风控策略、审批点 |
| 业务集成与产品化 | 入口、权限、SLA、工单、CRM、消息队列 | 集成方案、上线计划 |

## 四、学习路径/步骤

1. **场景拆解**：选高频、高价值、可容错场景，明确用户、任务、输入、输出、成功标准。
2. **定义 Agent 角色**：目标、边界、禁止事项、升级人工条件。
3. **设计工具与知识接口**：列出 API、数据库、RAG、知识源、参数与权限。
4. **搭建最小闭环**：LLM + 提示词 + 1 个工具 + 1 个知识库 + 简单记忆。
5. **评估调优**：建测试集，看成功率、工具调用准确率、成本、延迟。
6. **集成业务系统**：接 CRM、工单、订单、审批、消息渠道，补权限与审计。
7. **上线灰度与人机协同**：低风险自动，高风险人审，支持回滚。
8. **运营迭代**：Trace 复盘、Badcase 归因、知识/工具/策略持续优化。

## 五、典型应用场景

| 场景 | Agent 任务 | 工具/数据 | 核心指标 |
|---|---|---|---|
| 客服/售后 | 解答、查单、退换、建工单 | 知识库、订单 API、工单系统 | 解决率、转人工率 |
| 销售/营销 | 线索评分、内容生成、CRM 更新 | CRM、邮件、日历、知识库 | 转化率、跟进效率 |
| 运营 | 数据查询、日报、活动配置 | BI、数据库、运营后台 | 节省人力、准确率 |
| 研发/技术 | 告警排查、代码助手、工单处理 | 日志、监控、Git、CI/CD | MTTR、自动化率 |
| 内部流程 | HR/IT/财务问答与审批 | OA、HR 系统、财务系统 | 时效、合规率 |
| 产品 | 调研分析、需求整理、PRD 辅助 | 文档、问卷、用户反馈库 | 产出效率、质量 |

## 六、配套工具链

- 模型：OpenAI、Claude、Gemini、通义、文心、DeepSeek。
- 编排：LangChain、LlamaIndex、LangGraph、AutoGen、CrewAI、Dify、Coze、n8n。
- 工具协议：Function Calling、MCP、OpenAPI、Webhook。
- 知识/RAG：向量库、Elasticsearch、Pinecone、Milvus、Chroma。
- 记忆/状态：Redis、Postgres、对象存储。
- 可观测：LangSmith、LangFuse、Phoenix、OpenTelemetry。
- 评估：RAGAS、DeepEval、自定义评测集。
- 部署：FastAPI、Serverless、K8s、消息队列。
- 治理：鉴权、脱敏、审计、审批流、灰度开关。

## 七、常见误区

1. 为 Agent 而 Agent，简单流程硬做 Agent。
2. 工具过多、描述模糊，导致误调用。
3. 忽视权限、审计、越权与数据泄露。
4. 只调 Prompt，不优化工具、知识库与流程。
5. 无评估指标，靠体感判断效果。
6. 忽视延迟、成本与并发限制。
7. 没有人工兜底与回滚机制。
8. 把 RAG 当万能，不治理知识质量。
9. 多智能体过度设计，复杂度高于收益。
10. 上线即结束，缺少 Trace 与持续运营。

后续每个案例按以下接口填写，即可与课程方法论深度镶嵌。

| 编号 | 接口 | 填写内容 | 对应模块 |

### 8.2 深度镶嵌层级

- L1 概念映射：案例能对应课程概念。
- L2 流程映射：案例能画出 Agent Loop 与 SOP。
- L3 工具映射：案例能定义工具契约与调用链。
- L4 系统映射：案例能接入真实业务系统与权限。
- L5 运营映射：案例有指标、灰度、人审、复盘机制。

**使用方式**：每个案例按 I1–I13 填表，并标注 L1–L5 深度。未填接口视为案例未闭环；未达 L4 视为未完成业务集成；未达 L5 视为未形成运营闭环。
