# 012 AI 产品第一课·知识包

> 来源：YAI 课程版AI 对话抓取（conversation: 95888623-c7e7-468f-9de3-fc29e7cb1846，2026-09-30）
> 课程归属：一堂正课（AI 产品/技术系列）
> 用途：作为本营课程案例设计的「方法论底座」，案例内容与 AI 产品第一课方法论深度镶嵌

> 定位：面向产品经理/创业者的 AI 产品正课。不教模型训练，教如何把模型能力转化为产品价值。
> 关键词：AI 产品定义、人机交互、评估闭环、落地增长。
> 产出目标：能判断场景、写定义画布、设计人机协同交互、建立三层评估、走通 MVP 到落地路线。

## 1. 课程定位与目标

**定位**
从"模型能力"到"产品价值"的翻译课。核心不是追技术热点，而是回答：什么场景值得做、AI 做什么、人做什么、如何评估、如何落地。

**目标**
- 能判断一个场景是否适合 AI 产品化。
- 能输出 AI 产品定义画布与 MVP 方案。
- 能设计 Copilot / Assistant / Agent 等交互范式。
- 能建立模型层、产品层、业务层评估体系。
- 能识别成本、延迟、合规、数据与组织落地风险。

**适合**
产品经理、创业者、业务负责人、AI 应用开发者。
**不解决**
底层算法研究、大模型预训练、纯技术架构深水区。

## 2. 核心方法论 / 模型

### 2.1 AI 产品价值公式
**价值 =（模型能力 × 场景任务 × 交互效率 × 评估闭环）/（成本 + 风险）**
模型只是变量之一，场景、交互、评估、成本共同决定产品成败。

### 2.2 AI 产品定义画布
- 用户：谁在用？
- 任务：完成什么高频/高痛任务？
- AI 角色：替代、增强，还是创造新流程？
- 数据/知识：模型靠什么回答？RAG、微调还是工具调用？
- 交互：输入输出、人机分工、失败兜底。
- 评估：模型指标、产品指标、业务指标。
- 成本/风险：Token、延迟、合规、幻觉、维护。
- 边界：AI 不做什么，何时转人工。

### 2.3 人机协同分级
- L0 人工：AI 不参与。
- L1 辅助：AI 给建议，人决策。
- L2 协同：AI 执行，人审核。
- L3 自动：AI 自动执行，人异常介入。
- L4 自主：AI 闭环执行，高风险场景慎用。

### 2.4 交互四模式
- Copilot：嵌入工作流，辅助人。
- Assistant：对话式问答与任务协助。
- Agent：多步规划、调用工具、自动执行。
- Creator：内容/图像/视频/代码生成。

### 2.5 评估三层
- 模型层：准确、幻觉、安全、鲁棒。
- 产品层：有用、易用、信任、延迟、成本。
- 业务层：转化、留存、降本、增收、效率。

### 2.6 落地五步
**选场景 → 定边界 → 做原型 → 建评估 → 工程化。**

## 3. 关键知识模块

1. **AI 能力与边界**：LLM、RAG、Agent、多模态、微调、上下文、幻觉。
2. **产品定义**：场景筛选、AI 适配度、任务拆解、MVP、价值假设。
3. **交互设计**：Prompt、对话、多模态、反馈纠错、信任建立、兜底路径。
4. **评估体系**：测试集、离线/在线评估、A/B、红队、人工在环。
5. **数据与工程**：数据采集、标注、向量库、RAG、工具调用、监控。
6. **落地与增长**：ROI、成本延迟、合规、组织协作、规模化运营。

## 4. 学习路径 / 步骤

1. **诊断**：业务、用户、数据、技术、风险。
2. **选题**：高频、高痛、容错、数据可得、可验证、ROI 清晰。
3. **定义**：填写 AI 产品定义画布，明确 AI 不做什么。
4. **交互**：设计人机分工、输入输出、纠错与转人工。
5. **评估**：建测试集、指标、红队、上线标准。
6. **原型**：用 API/低代码搭 MVP，人工在环验证。
7. **小流量**：真实用户、真实任务、真实成本。
8. **工程化**：监控、迭代、成本控制、安全合规。
9. **规模化**：运营增长、组织流程、数据飞轮。

## 5. 典型应用场景

| 场景 | AI 角色 | 关键指标 |
|---|---|---|
| 知识问答/RAG | Assistant | 准确率、引用率、幻觉率 |
| 内容生成 | Creator | 采纳率、编辑成本、生成速度 |
| 智能客服 | Copilot/Agent | 解决率、转人工率、满意度 |
| 销售 Copilot | Copilot | 转化率、跟进效率、话术采纳 |
| 研发 Copilot | Copilot | 代码采纳、缺陷率、效率 |
| 数据分析 | Assistant/Agent | 查询准确、洞察有用、响应时间 |
| Agent 自动化 | Agent | 任务完成率、异常率、人工介入 |
| 多模态审核 | Agent | 召回、误杀、合规风险 |

## 6. 配套工具链

- **模型层**：OpenAI、Claude、通义、文心、开源模型。
- **编排层**：LangChain、LlamaIndex、Dify、Coze、n8n。
- **RAG/数据**：向量库、Embedding、文档解析、知识库。
- **评估层**：Promptfoo、LangSmith、W&B、人工评测表。
- **原型层**：Figma、V0、低代码、API Playground。
- **标注层**：Label Studio、标注规范、测试集管理。
- **分析层**：Amplitude、Mixpanel、埋点、A/B。
- **部署层**：云服务、API 网关、监控、日志、权限。

## 7. 常见误区

- 把 AI 产品当"模型套壳"，无场景定义。
- 追求 100% 准确，忽视失败兜底。
- 只做 demo，不建评估。
- 忽略 Token 成本、延迟、并发。
- 交互照搬传统 GUI，不设计纠错与信任。
- 场景大而全，不做 MVP。
- 无数据闭环，模型不迭代。
- 忽视合规、隐私、版权、安全。
- 无人工在环，高风险场景全自动。
- 技术驱动，而非用户任务驱动。

### 8.3 模块嵌入方式
- **微案例**：5 分钟引子，用于概念导入。
- **模块案例**：20 分钟拆解，对应一个方法论。
- **综合案例**：项目制，串起定义、交互、评估、落地。
- **反例案例**：展示失败模式，强化误区认知。

### 8.4 案例接口问题
- 用户是谁？任务是否高频高痛？
- AI 做什么？不做什么？
- 人机如何分工？失败如何兜底？
- 如何评估？成功与失败标准是什么？
- 成本、延迟、合规是否可接受？
- 数据飞轮如何形成？

### 8.5 一页式案例底座
**案例名称 → 用户任务 → AI 角色 → 人机分工 → 数据知识 → 交互流程 → 评估矩阵 → 成本风险 → 落地路线 → 复盘迭代。**

## 9. 一句话总结

**AI 产品第一课的本质：用定义画布选场景，用人机协同做交互，用三层评估控质量，用五步落地跑闭环。**
案例设计时，先套画布，再挂评估，再嵌交互与落地，即可与课程方法论深度咬合。
