> **授课要点（依据故事线 v1＋夙愿框架）**：
> - **初版 V1 锚（喂文档法，重点讲细）**：生图网站的本质＝网页界面＋调用第三方生图 API；对接三步：①调研多家接口文档（比稳定/参数/价格）②把**接口链接＋参数＋返回结果**喂给 AI ③它基本就能利用接口返回结果（写出调用/接入页面）。提示词模板：`"这是 XXX 生图接口的文档（链接+参数+返回示例），请帮我在我的网站里接入它：用户输入提示词→调这个接口→把返回的图片显示出来。"` 本质＝**把接口文档喂给它＝先让它学会，再让它干活**（G04 的 API 版）。
> - **V2 锚（备胎思维，本案例最有价值）**：不是技术问题，是**产品思维**——接口不稳定 → 连续接几家（Gemini/即梦/国外 GPT 模型等）→ 后台加"可配置"开关（哪个模型展示/干活，一句话的事）→ 接口挂一家站不断、用户无感。金句候选：`技术出问题不可怕，可怕的是没有备胎。`
> - **V3 锚**：接反馈三不要（不辩解/不慌/不单干）→ 问清楚"哪里不够"（界面太素像工具）→ 找对标即梦 → 拆骨架（拆哪几块：作品流/生成区/参数区＋配色怎么配）→ 换皮不换骨（回扣 D1下"复刻骨架，不抄内容"）。
> - **V4 锚（数字画布）**：复刻某网站的画布内容（用户已允忽略确认）→ 拆成**工作流**形式 → 沉淀"连续性生图"功能（风格锁定/参考图传递/连续迭代/批量出图）→ 从"出一张"到"出一套"，从单次工具到工作台。金句候选：`出图工具赚单张的钱，画布工作台赚"一套"的钱。`
> - **V5 锚（测试，内容直接落在大纲）**：功能多了要测 → 发现**域名不兼容＝用户访问加载很慢**（根因以讲师实情为准；解法方向：图片走 Storage CDN＋在线压缩）→ **全部让 AI 排障**：把报错/现象喂给它→给修法→再测→清零。**讲的故事（不展开名词）**：①写代码前先让 AI 写"会失败的测试"，代码有了客观裁判（TDD）②让 AI 用浏览器自己把整条路跑一遍，遇到 Bug 只记录现象、不让它自己动手修（E2E，防打补丁）③最后一条主路径（注册→登录→使用）**自己亲自测**（手工分组，最后防线）。金句候选：`报错不可怕，可怕的是你不把报错喂给 AI。`
> - **V6 锚（部署，内容直接落在大纲）**：Supabase＝开源 BaaS（"Firebase 开源替代品"，GitHub 已超 **10 万 star**）；核心是独立完整 **PostgreSQL 数据库**（每日自动备份）；封装 Auth（JWT/社交登录）/自动 API/存储（全球 CDN 285+ 城市＋图片在线优化）/实时/边缘函数/可视化面板；Free $0/月（500MB 库、无限 API 请求、自动备份、5GB 出站）；上手＝注册→新建项目（1-2 分钟）→图形化建表（不用写 SQL）→几行代码读写。**教学锚**：数据库不是黑盒，是一个"点几下就有的云数据库，还自带接口"——一个人做产品不用搭服务器。**部署四件**：前端网页＋Supabase（数据库/认证/存储/自动 API）＋Worker＝Edge Functions（编排调用生图 API）＋Storage CDN（图片分发）。存什么：用户/生成记录/图片 URL/后台配置（V2 开关数据在这）。**重磅连线**：Supabase 官方自己发布了开源 **Agent Skills**（含 SKILL.md）＋MCP＋Plugin 来教 AI 用对 Supabase——官方都用"把开发方法做成 skill"这套，D1下 的 Skill 定义在真实世界被印证。
> - **数据锚（贯穿）**：7毛→3毛/张；1000 张省 400 元/天，一个月约 1.2 万；400+ 付费、200+ 年会员；零成本起步。**不是靠感觉经营，是靠数据经营。**
> - **"沉淀 skill"彩蛋（收在 V6 块尾，不展开）**：一句话——"六版做下来，我把方法都沉淀成了 skill，下次直接叫它干。连 Supabase 官方都这么干。"回扣 D1下 Skill 定义；不给学员加任务。
> - **教法**：全程不亮结果不抽屏幕，抽查提问＋同桌互助；三波反馈用"停·看·问"做状态切换（连续讲解≤7-8 分钟必切换）；先完整演示（喂文档法/后台开关/对标提示词），再 60-90 秒微练习。

> **开发工作流沉淀（授课取用，来源：`10 其他资料/夙愿·AI Agent聪明度管理框架.md`；素材层全量见故事线附录A）**：
> - **9 步闭环**（讲师真实开发法，课堂隐形使用，不亮名词）：`Issue → Grade(榨干需求) → 原型(验证方案) → To PRD(沉淀文档) → To Issue(垂直切片) → TDD(测试驱动) → 代码审查 → E2E测试 → 手工分组测试 → Bug Fix(7阶段) → 循环`
> - **与案例 V1~V6 逐版对应（9 步闭环体现在每个案例版本上）**：
>   - **V1 初版** ＝ Issue → Grade → To PRD → 原型（朋友一句话=Issue；五行需求=Grade 榨干；需求/开发文档=To PRD；AI 出第一版=原型）
>   - **V2 可配置** ＝ To Issue 垂直切片（接口不稳定→每家 API 一个独立切片→并行接入→后台可配置）
>   - **V3 高大上** ＝ 原型验证（对标即梦=先给范本再换皮，方案用数据说话）
>   - **V4 画布** ＝ To Issue＋原型（复刻标杆→拆工作流→逐功能切片实现）
>   - **V5 测试** ＝ TDD → E2E → 手工分组 → Bug Fix（让 AI 排障=7 阶段修复的简化版）
>   - **V6 部署** ＝ 完成后收尾（Supabase＋Worker）
> - **测试三件**（V5 讲的故事已含）：TDD 客观裁判／E2E 只记录不修／手工分组最后防线
> - **部署四件**（V6 讲的故事已含）：前端＋Supabase＋Edge Functions＋Storage CDN
