### 2. 什么是 Skill（1:14–3:00）：一个技能＝流程＋配方＋工具＋材料

- 金句开场："到底什么是 Skill？"
- **厨师类比（核心教学道具）**："比如说你是一个厨师" —— 技能1 炒菜。
  - 炒菜这个技能包含四样东西：
    - **流程**：炒菜顺序（先做什么后做什么）
    - **配方**：油温多高、盐放多少（参数与标准）
    - **工具**：煤气灶、炒锅
    - **材料**：独家食材
- **结构映射（上屏图）**：技能1 炒菜 ＝
  - 流程 → **SKILL.md**（怎么做的主流程说明）
  - 配方 → **references**（参数/标准/参考文档）
  - 工具 → **scripts**（可执行的脚本）
  - 材料 → **assets**（素材：图片、logo 等）
- 一句话：**Skill（技能）文件夹 = SKILL.md + references + scripts + assets**，"我们先来个简单的"。
- 与提示词的关系：我们跟大模型的交互"其实都离不开提示词"，但——
- **核心论断（上屏大字）**：**提示词 ≠ Agent Skills；Skill 在工程上存在优势，比普通提示词更有用——"要多很多"。**

### 3. 创建 Skill（3:00–6:12）：实测——写一个 SKILL.md 就成

- 实操前先装环境（讲师演示用）：Agent Skills 指南（Claude Code 版）→ 安装 AI 编程工具 **Antigravity**（免费；Cursor/VSCode 也可以），登录、装中文插件。
- 建文件夹：`~/Claude Code/qiuzhi-project/claude/skills/qiuzhi-creative/`（**Skills 必须放在指定文件夹下**——Claude Skills 规定：项目名 → .claude → skills）。
- **SKILL.md 就两部分**（上屏重点）：
  - **元信息（metadata）**：`name`（技能名）＋ `description`（一句话说清"它是干什么的"，决定 AI 什么时候调用它）。
  - **指令（instruction）**：具体干活规则——如「品牌核心元素」（品牌名/风格/IP形象/配色/Slogan）、「你的任务」（用户要海报/易拉宝/工服/包装盒时怎么输出）、「输出格式」（创意主题/视觉风格/画面构成/细节建议）。
- 秋芝餐厅实战 SKILL.md（课程可直接引用）：
  - `name: qiuzhi-creative`
  - `description: 为秋芝餐厅生成符合品牌调性的物料设计创意……`
  - `## 品牌核心元素`（品牌名：秋芝餐厅；风格：年轻、潮流、有网感；IP：3D 卡通葫芦；主色：薄荷绿 #50DEB5；Slogan：A FRESH MODERN BITE / 健康轻食主义）
  - `## 你的任务`（海报、易拉宝、工服、包装盒等 → 输出设计创意）
  - `## 输出格式`（### 创意主题 ……）
- 放好即生效：AI 对话里自动出现——"你有哪些 skill？目前我有以下 skill 可用：qiuzhi-creative……" **"真的就创建完了。"**

### 4. Skill 的按需加载（6:12–15:01）：为什么 Skill 更省、更准

- 核心机制："在于它是**按需加载**的。"
- 工作过程：AI **先只看元信息**（name＋description，极小）→ 判断要不要用 → 需要时**才去加载指令层**（SKILL.md 全文）→ 需要时**再读资源层**（references/scripts/assets）。"他才会去看""他才会去加载"。
- 三个好处（上屏）：
  1. **省一堆 token**（不用的内容不加载）
  2. **没有其他 Skill 干扰**（元信息精准匹配，不会串台）
  3. **回答更精准**（要用什么才加载什么）
- 反面案例（为什么不能把要求全塞进提示词）：把"常规/实体/线上"所有物料要求一次性塞进去 → **token 浪费**＋**造成信息干扰**。
- **Skill 三层结构（按需加载，核心上屏图）**：
  1. **元信息**（name＋description）——**始终加载**
  2. **指令层**（SKILL.md 里的具体指令）——**按需加载**
  3. **资源层**（references 规格文档 / scripts 脚本 / assets 素材）——**按需加载，直接执行、不费 token**
- references 怎么用（秋芝餐厅实例）：
  - SKILL.md 里写明：`当用户需要做线下实体物料时，读取 Physical-Specs.md`；`做社交媒体物料时，读取 Social-Specs.md`。
  - 引用表：类型｜引用文档｜涵盖范畴（实体物料→references/Physical-Specs.md→工服/餐盒/菜单/易拉宝；社交媒体→references/Social-Specs.md→小红书/公众号/微博九宫格/长图）。
  - "那这个实体物料规格点 md"：员工服装（颜色/Logo 位置/材质）、棒球帽、围裙……全在 references 里。
- scripts＋assets 怎么用：
  - `scripts/generate_image.py` 生图脚本；`assets/logo_mint.png、logo_white.png` 参考图。
  - SKILL.md 指令：生成图片前调用脚本、把 assets 图片作为参数传入。
- **完整闭环演示（课程可照搬的"哇点"）**：
  - 用户一句："帮我做一张**周六饮料免费**的实体海报"
  - AI：发现并加载 qiuzhi-creative Skill → "首先让我查看一下实体物料的规格要求" → Read Physical-Specs.md → 构造提示词 → 调用 generate_image.py → **产出带 logo 的成品海报**（周六饮料免费 / FREE DRINKS EVERY SATURDAY / 每周六全天·堂食免费畅饮）。
  - 对比：没有 Skill 前，做一张图要 5 步——拷贝提示词→打开软件→粘贴提示词→生成图片→下载保存；有 Skill 后，"**他就能一句话**"搞定。
  - 且物料风格一致："做实体餐盒的时候……风格都很一致"。

### 5. Skill Creator（15:01–17:12）：不用手写，让 AI 帮你造 Skill

- 过渡："这又是写 Markdown？""其实也不是我手写的。"
- 装一个现成的 **Skill Creator**（qiuzhi-skill-creator，一个文件夹：SKILL.md＋references＋scripts），它本身就是一个 Skill。
- Creator 的原理（Claude Code 官方 skill-creator）：把复杂任务转化为**高度工程化的 SOP（标准作业流程）**，**分阶段执行，每个阶段都要与用户充分交流确认**。
- 它的提问方式（可直接学的"方法论"）：**用"大白话＋选择题"盘问需求（需求挖掘 Discovery）**——"你想做一个什么样的 Skill？简单来说，你希望只要【输入】什么，AI 就会【输出】什么？"
  - 例："我要做一个名称为 qiuzhi-creative 的 skill，为秋芝餐厅的物料设计提供整套方案。"
  - Creator 逐步追问：需要什么类型的物料？（多选）→ 用户会提供什么素材？（logo 参考图 / API key＋说明文档）→ 品牌指南有没有？（没有，按现有资料推测）……
- 收集完需求，Creator **自动生成所有 Skill 文件**：SKILL.md、references（验证 API 文档放进去）、assets（读 logo 图片建品牌指南）、scripts。
- 成果：之后一句话生成物料，"**风格都很一致**"（示例：秋芝工作日能量套餐 ¥29.9 起推广图）。

### 6. 现成的 Skill（17:12–18:58）：不用造，拿来就能用

- 现成资源入口：**Agent 技能库 / Agent Skills 合集 / 集合网站和 Skill 仓库**。
- 通用型 skills（可直接展示清单）：做PPT、文档处理、表格处理、PDF处理、NotebookLM、图片生成、动画生成、技能创建、前端设计、多步骤规划。
- 官方文档核心机制：**渐进式披露（Progressive Disclosure）＝ Discovery（探索）→ Activation（激活）→ Execution（执行）**，"效果明显大幅提升"。
- 什么场景最适合做成 Skill（**金句**）：**结果要求明确 ＋ 有经验和方法**的重复性工作。
- 高频工作举例（可直接引的三种职业）：
  - 打工人·周报 Skill（销售周报：销售额/目标完成率/订单/新增客户 → 自动生成图表＋总结）
  - 创作者·图文编辑 Skill（文章配图："你总是要给你的文章配图"）
  - 法务·审合同 Skill（房屋租赁合同审查）
  - "那就做一个。"

## 五、可直接上屏的金句（候选）

1. **Skill 就是技能：流程＋配方＋工具＋材料，打包成一个文件夹。**
